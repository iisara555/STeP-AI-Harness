# STeP Event Run of Show

## Purpose

เป็นด่าน **execution** ของงาน event ต่อจากขั้นคอนเซ็ปต์ แปลง agenda ระดับวาระให้เป็น **คิวที่ใช้จริงบนเวที** ซึ่งทีมพิธีกร จอ เสียง แสง เวที และ PM อ่านพร้อมกันได้จากตารางเดียว

`event-concept` ตัดสินว่างานนี้คืออะไร Skill นี้ตัดสินว่า 08:33 เกิดอะไรขึ้นและใครรับผิดชอบ

ทำงาน 2 โหมด:
- **Mode A — Build** จาก agenda, บรีฟ หรือ TOR ที่มีเวลาระดับ block
- **Mode B — Review** จาก sequence เดิมที่ทีมร่างไว้แล้ว

ไม่ใช่การตรวจ TOR การวางแผนงบประมาณ หรือการทำ Gantt ของโครงการ

## เมื่อควรใช้

ใช้เมื่อผู้ใช้พูดในลักษณะ:
- "ช่วยทำรันคิวเวทีจากกำหนดการนี้"
- "ขอ sequence เวทีแบบละเอียด มีคิวจอ คิวเสียง"
- "ทำ cue sheet ให้ทีม AV"
- "เรียงลำดับพิธีเปิดทีละคิว"
- "ตรวจ sequence นี้ว่าเวลาตรงไหม ใครยังไม่มีชื่อ"
- "ทำ run through สำหรับซ้อมใหญ่"

**Anti-trigger:**
- คอนเซ็ปต์งาน ธีม ผังบูธ เส้นทางผู้เข้าชม → `event-concept`
- แผนงาน งวดงาน หรืองบประมาณของโครงการ → `project-plan`
- ทำหรือแก้สไลด์ VTR ที่คิวอ้างถึง → `presentation-design`
- ตรวจ TOR หรือร่างขอบเขตงานจ้างออแกไนเซอร์ → `tor-review`, `tor-government-writing`
- เอกสารมีเบอร์โทร ทะเบียนรถ หรือข้อมูลการเดินทางของบุคคล → `data-privacy-compliance`

## Inputs

ขั้นต่ำสำหรับ Mode A:
- ชื่องาน วันที่ และสถานที่
- agenda ระดับ block พร้อมช่วงเวลา

ขั้นต่ำสำหรับ Mode B:
- ไฟล์หรือข้อความ sequence เดิม

มีแล้วดี: จำนวนผู้เข้าร่วม ชื่อพิธีกร จำนวนจอและตำแหน่ง รหัส Scene ที่ทีม AV ใช้อยู่ รายการ VTR และสไลด์ ช่วงเวลาขนของเข้า และเวลาที่ต้องจบแน่นอน

ก่อนอ่านเอกสารแนบให้ใช้ Privacy Gate และลด PII ที่ไม่จำเป็น

ข้อมูลที่ขาดให้เขียน `รอยืนยัน` ห้ามเดาเวลา ชื่อ หรือตำแหน่ง

## Source

- แหล่งหลักคือ **agenda บรีฟ หรือ sequence ที่ผู้ใช้ให้มา** สำหรับโครงสร้างคิวและ lane นั้น `ไม่มี Source ภายนอกที่จำเป็น`
- ถ้อยคำภาษาไทยที่พิธีกรพูดและคำกล่าวบนเวที อ้าง `step-writing-rule`
- ชื่อผู้รับผิดชอบและข้อมูลติดต่อ อยู่ใต้ `data-classification-rule`
- จุดที่ต้องให้คนอนุมัติก่อนใช้จริง อ้าง `human-approval-rule`
- คิวที่ระบุโลโก้ Key Visual หรือองค์ประกอบแบรนด์บนจอ อ้าง `step-brand-ci-guideline`
- รหัส Scene/Format และตัวย่อชื่อคน **ไม่ใช่ Source ขององค์กร** เป็นข้อตกลงรายงานกับทีม AV จึงต้องยืนยันก่อนใช้เสมอ

แม่แบบในโฟลเดอร์นี้: `references/lane-contract.md`, `references/review-checklist.md`, `templates/run-of-show-template.md`, `templates/cue-enums-template.md`

## Workflow

1. **Mode Gate** — ถ้ามี sequence เดิมแนบมา ให้ทำ Review ก่อนเสมอ แล้วจึงเสนอ Build ฉบับแก้ ถ้ามีแต่ agenda ให้ทำ Build
2. **Privacy Preflight** — ใช้ Privacy Gate ก่อนอ่านไฟล์แนบ ตัดค่าในคอลัมน์ติดต่อออก และห้ามคัดลอกเบอร์โทร ทะเบียนรถ หรือเลขเที่ยวบินเข้าไปในผลลัพธ์
3. **Block extraction** — หาแถวที่ทำหน้าที่เป็นวาระ แล้วดึง `Block No.`, `Block`, `Block Time`, `Block Duration` คอลัมน์ที่ทำหน้าที่นี้ต่างกันในแต่ละเอกสาร ให้ระบุก่อนว่าเอกสารนี้ใช้คอลัมน์ไหน
4. **Cue decomposition** — แตกเป็นหนึ่ง action ต่อหนึ่งแถวตาม `references/lane-contract.md` ใช้อะตอมพิธีกรมาตรฐาน: MC เชื่อม, MC เชิญ, วิทยากรขึ้นเวที, เนื้อหา, MC ขอบคุณ, ลงเวที
5. **Lane assignment** — เติมเฉพาะ lane ที่งานนี้มีจริง lane ที่ไม่มีข้อมูลเลยให้ลบออกจากตารางและบันทึกว่า `ไม่ใช้ในงานนี้` รหัส Scene/Format ไปอยู่ใน `templates/cue-enums-template.md` โดยตั้ง `รอยืนยัน` ทุกแถว
6. **Time and timer reconciliation** — คำนวณ `Cue Duration` เทียบผลรวมกับ `Block Duration` ที่ต้นทางระบุ บังคับ `Timer` ไม่เกิน `Cue Duration` หาคิวที่หลุดออกนอกกรอบ block และแปลงฟอร์แมตเวลาให้เป็นแบบเดียว
7. **Ownership** — ทุกคิวต้องมี `Lead` หนึ่งคน `Support` เขียนเป็น `ชื่อ : งานย่อย` คิวที่ไม่มี Lead ขึ้นเป็น finding ไม่ใช่ช่องว่าง
8. **Assemble** — Mode B ไล่ `references/review-checklist.md` แล้วออกตาราง findings ส่วน Mode A ออกตารางคิวพร้อม Open Items ทั้งสองโหมดติดป้าย provenance ทุกค่า และเติมคิวสำรองต่อ block เป็น `PLANNING_ASSUMPTION`

## Authority

AI ช่วยได้: แตกคิว คำนวณเวลา จัด lane ร่างบทเชื่อมของพิธีกร และชี้ข้อบกพร่องที่พิสูจน์ได้จากเอกสาร

ต้องให้มนุษย์ตัดสิน:
- ลำดับเกียรติ ลำดับการเชิญ VIP และถ้อยคำในคำกล่าวเปิดงานหรือหนังสือเชิญ — `official-signing`
- การจ้างทีมแสงเสียง จอ LED หรือออแกไนเซอร์ และวงเงิน — `procurement-approval`, `budget-allocation`
- การอนุมัติให้ใช้ sequence ฉบับนี้จริงบนเวที เป็นอำนาจของ show caller และเจ้าของงาน

**AI ไม่ยืนยันว่าคิวนี้ทำทันจริงในเวลาที่กำหนด** ความเป็นไปได้จริงพิสูจน์ได้จากการซ้อมเท่านั้น ไม่ใช่จากเอกสาร

## Handoff

- คอนเซ็ปต์ ธีม หรือผังโซน → `event-concept`
- สไลด์หรือ VTR ที่คิวอ้างถึง → `presentation-design`
- แผนงานและงวดงานก่อนถึงวันงาน → `project-plan`
- ข้อมูลส่วนบุคคลในคอลัมน์ติดต่อหรือผู้สนับสนุน → `data-privacy-compliance`
- ขอบเขตงานจ้างแสงเสียงหรือสถานที่ → `tor-government-writing`
- ภาษาไทยของคำกล่าวและบทพิธีกร → `step-writing`
- หนังสือเชิญ VIP → `thai-official-documents`

พร้อมส่งต่อเมื่อ: ทุก block มี duration ที่ตรวจแล้ว ทุกคิวมี Lead รหัสใน Cue Enums ถูกยืนยันแล้ว และ Open Items ว่างหรือมีเจ้าของพร้อมกำหนดวัน

## Guardrails

- ห้ามแต่งชื่อวิทยากร ตำแหน่ง เวลา หรือชื่องานที่ต้นทางไม่มี ชื่อทางการที่สงสัยว่าพิมพ์ผิดให้ flag ไว้ **ห้ามแก้เอง**
- ห้ามเขียนเบอร์โทร ทะเบียนรถ เลขเที่ยวบิน หรือเวลาเดินทางของบุคคลลงในตารางที่แจกทีมงาน
- ห้ามเดาความหมายของรหัส Scene/Format หรือตัวย่อชื่อคน ต้องเป็น `รอยืนยัน`
- ห้ามปล่อยคิวที่ไม่มี Lead ให้เป็นช่องว่าง ต้องขึ้นเป็น finding
- ห้ามใช้ merged cell หรือช่องว่างแทนความหมายว่า "เหมือนแถวบน" ในผลลัพธ์
- ห้ามปรับเวลาที่ต้นทางระบุให้ลงตัวเอง ให้รายงานส่วนต่างแทน
- ห้ามนำไฟล์งานเก่ามาใช้ซ้ำโดยไม่ล้างชื่องาน ชื่อคน และข้อมูลติดต่อออกก่อน
- ห้ามอ้างว่าสร้างสเปรดชีตสำเร็จถ้ายังไม่มี output reference จริง
- ถ้าเป็นวันงานและทีมกำลังใช้ชีตอยู่ ห้ามปรับโครงสร้างของเดิม ให้สร้างเวอร์ชันใหม่
