# Model → Syntax Family Mapping

**Last reviewed:** 2026-09-20
**สถานะ:** working reference ที่เปลี่ยนได้ตลอด ไม่ใช่ Capability Gate

Capability Gate ตัดสินจาก **รูปแบบการเขียน prompt ที่เครื่องมือรับ** ไม่ใช่จากชื่อรุ่น ตารางนี้ใช้เป็นจุดตั้งต้นเท่านั้น ถ้าไม่แน่ใจให้ถามผู้ใช้ว่าเครื่องมือรับ prompt แบบใด

## ตารางตั้งต้น

| เครื่องมือ / รุ่น | Family ตั้งต้น | หมายเหตุ |
| --- | --- | --- |
| Nano Banana Pro, Nano Banana 2 (Gemini image) | A, และ D เมื่อส่งภาพเข้าไปแก้ | รับภาษาธรรมชาติยาวได้ดี และรับ image input |
| GPT Image 1.5 | A, และ D เมื่อแก้ภาพ | อธิบายเป็นประโยคได้ ไม่ต้องใช้ tag |
| Seedream 5.0 | A | ภาษาธรรมชาติ ตรวจวิธีตั้ง ratio ในเครื่องมือ |
| Midjourney | C | ใช้ `--ar`, `--no` และ flag อื่นตามเวอร์ชัน |
| Stable Diffusion และ UI ตระกูลเดียวกัน | B | tag คั่นจุลภาค รองรับ negative prompt และ weight |
| Flux | A หรือ B ขึ้นกับ UI | ตรวจว่า UI ที่ใช้รับประโยคหรือ tag |
| เครื่องมือ inpaint / edit ทุกตัว | D | ต้องยืนยันว่ารับ image input จริง |

## กติกา

1. **ห้าม hard-code ชื่อรุ่นเป็นเงื่อนไขในการทำงาน** ตารางนี้ช่วยเดาเร็วขึ้นเท่านั้น
2. ชื่อรุ่นที่ระบบไม่รู้จัก **ห้ามเดา family** ให้ถามว่าเครื่องมือรับ prompt แบบใด เช่น พิมพ์เป็นประโยค พิมพ์เป็นคำคั่นจุลภาค หรือมี flag
3. Prompt Spec เดิม render ข้าม family ได้ ไม่ต้องเริ่มใหม่เมื่อผู้ใช้เปลี่ยนเครื่องมือ
4. เมื่อผู้ใช้ไม่ทราบ family ให้ใช้ A ชั่วคราวและแจ้ง assumption สั้น ๆ
5. ความสามารถของแต่ละรุ่นเปลี่ยนเร็ว **ห้ามอ้างว่ารุ่นใดทำอะไรได้หรือไม่ได้** ถ้าไม่ได้ทดสอบในงานจริง ให้บอกผู้ใช้ทดสอบแล้วปรับ Spec

## ข้อจำกัดที่พบบ่อยและไม่ขึ้นกับรุ่น

- **ข้อความภาษาไทยในภาพ** ยังผิดรูปสระและวรรณยุกต์บ่อย ค่าเริ่มต้นคือ `EXCLUDE` ข้อความ แล้วเว้น `TEXT_SPACE`
- **โลโก้และตราสัญลักษณ์** โมเดลจะสร้างของปลอมที่ดูคล้ายของจริง ต้อง exclude เสมอ แล้ววาง official asset ทีหลัง
- **ตัวเลข กราฟ และหน่วยวัด** ไม่น่าเชื่อถือ ห้ามใช้ตัวเลขที่โมเดลสร้าง
- **นิ้วมือ ใบหน้า และโครงสร้างอุปกรณ์** ยังผิดได้ ให้ตรวจก่อนส่งงานทุกครั้ง
