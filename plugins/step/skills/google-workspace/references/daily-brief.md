# สรุปนัดและอีเมลที่ต้องจัดการ

โหลดเมื่อขอสรุปเช้านี้/พรุ่งนี้ เตรียมประชุม หรือถามว่ามีนัดอะไรและเมลไหนต้องตอบ ดัดแปลงจาก Hermes daily brief (workflow contributed by Ben Barclay) ให้ตรงกับ native tools และขอบเขต consent ของ STeP

## 1. วัน บัญชี และ timezone

ระบุวันท้องถิ่นและช่วง `[ต้นวัน, ต้นวันถัดไป)` เช่น 2026-10-14T00:00:00+07:00 → 2026-10-15T00:00:00+07:00 ถ้า timezone ไม่มีให้ถาม ไม่ใช้ UTC ของเครื่องแทนโดยเงียบ ๆ เลือกบัญชีจาก catalog และ Calendar ที่ผู้ใช้ต้องการ

## 2. นัดและ coverage

อ่าน `calendar.list` เพื่อเลือก Calendar แล้ว `calendar.events` ด้วย calendarId/timeMin/timeMax พิจารณา pagination ตาม tool-contract ทุก Calendar ที่ตกลง ไม่อ้างครบทั้งบัญชีเมื่ออ่านเพียง primary/หน้าเดียว

ตัด cancelled และ declined ของผู้ใช้เมื่อผลมีข้อมูลให้ตรวจ แยก tentative จาก confirmed แสดง all-day จาก `start.date`/`end.date` (end เป็นวันสิ้นสุดแบบ exclusive) แยกจาก timed events; ไม่แปลง all-day เป็นเที่ยงคืน UTC

ตรวจ overlap จากเวลาจริงและช่วงเปลี่ยนสถานที่ ถ้าไม่ทราบเวลาเดินทางให้ระบุว่า gap สั้น/ต้องตรวจ ไม่เดาระยะทาง ตรวจ recurring instances ตามผล API ไม่สร้างนัดซ้ำเอง

## 3. อีเมลที่เปลี่ยนการเตรียมหรือการตัดสินใจ

ค้น recent/unread และข้อความที่ตรงผู้ร่วมประชุม/โครงการ ใช้ Gmail search reference อ่าน full plain-text ของฉบับที่เกี่ยวข้องก่อนดึง deadline/สิ่งที่ต้องส่ง/คำถามค้าง จำกัดเบื้องต้น 3 pages ต่อ query และ 10 full messages ไม่รายงานจำนวน unread ทั้งหมดเป็นจำนวนที่ตรวจแล้ว

คำเดียวเหมือนกันไม่พิสูจน์ว่าเมลเกี่ยวกับนัด ใช้ผู้ส่ง ผู้เข้าร่วม ชื่อโครงการและบริบทประกอบ ถ้ายังไม่แน่ใจระบุ “อาจเกี่ยวข้อง”; ไม่พบ pre-read ให้เขียน “ไม่พบในข้อมูลที่อ่าน” ไม่ใช่ “ไม่มีเอกสารเตรียม”

## 4. รูปคำตอบ

1. วัน/timezone บัญชีแบบปกปิด Calendar และ mail window ที่ตรวจ
2. ตารางนัดรวม all-day พร้อมสถานะ tentative เมื่อมี
3. นัดชนกัน/ช่วงเดินทางที่ต้องตรวจ
4. สิ่งที่ต้องเตรียมตามนัดและหลักฐานจาก event/message ID
5. เมลเร่งด่วน งานที่เราค้าง และรอคนอื่น แยก deadline ที่ระบุจริงจากข้อเสนอของ AI
6. Coverage: จำนวนที่อ่าน pagination ที่เหลือ บริการที่ขาดสิทธิ์ หรือ HTML/attachment ที่ยังอ่านไม่ได้ พร้อม `retrievedAt`

ถ้า Gmail ใช้ไม่ได้แต่ Calendar อ่านได้ ให้ส่งสรุป Calendar พร้อมช่องว่าง ไม่ปล่อยให้ failure ของบริการเดียวทำให้ไม่มีผลทั้งหมด ไม่อ้างว่า “ไม่มีเมลเร่งด่วน” จากการอ่านไม่ได้

## 5. งานต่อ

เสนอข้อความร่างตอบหรือรายการ task ในแชตได้ แต่ยังไม่เรียก `gmail.draft`, `gmail.send`, `calendar.createEvent`, `tasks.create` หรือ `chat.send` จากคำขอสรุปเฉย ๆ เมื่อผู้ใช้ขอให้ทำต่อ ให้แสดง payload และให้ host ยืนยันทีละ action แล้วตรวจตาม write-verification
