# สำนวนที่ฟังออกว่า AI เขียน (ภาษาไทย)

ใช้ตรวจรอบสุดท้ายก่อนส่งข้อความ เป้าหมายคือให้ข้อความอ่านเหมือนคนในทีมเขียน ไม่ใช่ตัดคำตามรายการแบบกลไก
คำในรายการใช้ได้ถ้าจำเป็นจริง ปัญหาคือเมื่อคำเหล่านี้มาแทนเนื้อหา หรือมาเป็นกลุ่ม

ดัดแปลงหมวดหมู่จาก `avoid-ai-writing` (Conor Bronsdon, MIT) แล้วเขียนตัวอย่างใหม่สำหรับภาษาไทยและงานของ STeP ที่มาอยู่ใน [third-party-methods.md](../../../docs/third-party-methods.md)

## ตัดหรือเขียนใหม่ทุกครั้ง

| รูปแบบ | ตัวอย่าง | แก้เป็น |
| --- | --- | --- |
| เปิดด้วยบริบทกว้างเกินเรื่อง | "ในยุคที่เทคโนโลยีเปลี่ยนแปลงอย่างรวดเร็ว…" | เริ่มที่เรื่องที่จะบอกเลย |
| ขยายความสำคัญเกินจริง | "ถือเป็นก้าวสำคัญที่จะยกระดับ…อย่างยั่งยืน" | บอกผลที่เกิดขึ้นจริงพร้อมตัวเลขหรือสิ่งที่เปลี่ยน |
| โครง "ไม่ใช่แค่…แต่ยังเป็น…" | "ไม่ใช่แค่งานสัมมนา แต่เป็นพื้นที่แห่งการเรียนรู้" | บอกว่างานมีอะไร |
| ปิดท้ายแบบแชตบอต | "หวังว่าข้อมูลนี้จะเป็นประโยชน์", "หากมีคำถามเพิ่มเติมสามารถสอบถามได้เสมอ" | ตัดออก หรือใส่ช่องทางติดต่อจริงถ้าจำเป็น |
| อ้างผู้เชี่ยวชาญลอย ๆ | "ผู้เชี่ยวชาญหลายท่านมองว่า…" | ระบุชื่อหรือแหล่ง หรือตัดออก |
| คำถามล่อความสนใจ | "คุณเคยสงสัยไหมว่า…?" ในข้อความภายใน | เข้าเรื่องตรง ๆ |

## ระวังเมื่อเจอตั้งแต่ 2 คำในย่อหน้าเดียว

ขับเคลื่อน, ยกระดับ, ครบวงจร, อย่างยั่งยืน, บูรณาการ, ในทุกมิติ, อย่างมีประสิทธิภาพ, ตอบโจทย์, เชื่อมโยง, เปิดมิติใหม่, แห่งอนาคต, อย่างไร้รอยต่อ

คำเหล่านี้ใช้ได้เมื่อมีเนื้อหารองรับ เช่น "บูรณาการข้อมูลจาก 3 ระบบเข้าตารางเดียว" แต่ถ้าลบออกแล้วความหมายไม่หายไป ให้ลบ

## โครงสร้างที่ฟังออก

- ทุกย่อหน้าขึ้นด้วย "นอกจากนี้", "อย่างไรก็ตาม", "ทั้งนี้" ติดกันหลายย่อหน้า
- จัดทุกอย่างเป็นข้อ ๆ ที่มีแต่คำนาม เช่น "• ประสิทธิภาพ • ความยั่งยืน • นวัตกรรม" โดยไม่มีประโยคบอกว่าหมายถึงอะไร
- ตัวหนาทุกบรรทัด หรือใส่อีโมจินำทุกหัวข้อในข้อความทางการ
- ไล่ของ 3 อย่างเสมอ ("รวดเร็ว แม่นยำ และปลอดภัย") ทั้งที่มีจริงแค่ 1–2 อย่าง
- สรุปซ้ำสิ่งที่เพิ่งพูดไปในย่อหน้าสุดท้าย
- ใช้คำเชื่อมแปลจากภาษาอังกฤษ เช่น "ซึ่งนั่นหมายความว่า", "ในแง่ของ…", "มันคือ…"

## สิ่งที่ไม่ต้องแก้

- ภาษาราชการตามแบบของ `thai-official-documents` เช่น "จึงเรียนมาเพื่อโปรดทราบ" เป็นรูปแบบที่กำหนด ไม่ใช่สำนวน AI
- ศัพท์เทคนิคหรือชื่อโครงการที่มาจากต้นฉบับ
- คำที่ผู้ใช้เขียนมาเองและขอให้คงไว้

## ตรวจแล้วต้องไม่เสียอะไร

การเกลาสำนวนต้องไม่เปลี่ยนข้อเท็จจริง ตัวเลข ผู้รับผิดชอบ สถานะ หรือคำมั่น ตาม Guardrails ของ `step-writing`

## เขียนให้คนที่ไม่รู้เรื่อง IT

เริ่มจากสิ่งที่ผู้อ่านต้องรู้ เช่น “อ่านคำตอบจาก AI ไม่สำเร็จ ลองอีกครั้ง” ให้รายละเอียดระบบตามหลังเมื่อจำเป็น
คำแนะนำต้องใช้ชื่อปุ่มที่มีจริง และไม่เดาสาเหตุของปัญหา

| คำในระบบ | คำที่พนักงานอ่าน |
| --- | --- |
| Skill | ตัวช่วยงาน (อธิบายชื่อ Skill ครั้งแรก) |
| Model | รุ่น AI |
| API key | รหัสเชื่อมต่อ (API key) |
| Workspace ในขั้นเลือกที่เก็บไฟล์ | โฟลเดอร์ทำงาน |
| Runtime | โปรแกรมเชื่อมต่อ AI |
| Error code | รหัสสำหรับแจ้งปัญหา |

ใช้ศัพท์เดิมได้เมื่อเป็นชื่อช่องของบริการอื่น ชื่อเฉพาะ คำในเอกสารตามแบบ หรือเมื่อผู้ใช้ขอรายละเอียดทางเทคนิค
ข้อความขออนุญาตต้องบอกบริการปลายทาง ข้อมูลที่จะส่ง ขอบเขตการอนุญาต และค่าใช้จ่ายที่เกี่ยวข้องครบ
อย่าย่อจน “รอตรวจ” กลายเป็น “อนุมัติแล้ว” หรือจนเงื่อนไขสำคัญหายไป

แนวทางตรวจซ้ำนี้อ่านประกอบกับ [Humanizer 3.1.0](https://github.com/blader/humanizer/blob/d4b81278e6604e237bf32f0f7ce5c217aee94269/SKILL.md)
โดยเขียนคำแนะนำและตัวอย่างภาษาไทยใหม่สำหรับพนักงาน STeP ดูที่มาใน [third-party-methods.md](../../../docs/third-party-methods.md)
