# วันที่ เลขไทย และจำนวนเงินในร่างเอกสาร

คู่มือวิธีการสำหรับ Skill และ STeP Desktop ไม่ใช่ระเบียบสารบรรณหรือนโยบายการเงิน ข้อมูลตัวอย่างทั้งหมดเป็นข้อมูลสังเคราะห์

## วันที่

- เก็บค่าต้นฉบับไว้ก่อนจัดรูปแบบ เลขไทย ๐–๙ แปลงเป็นเลขอารบิกได้ในช่องตัวเลขโดยคงค่าเดิม
- วันที่ยุคปัจจุบันที่มีปีครบสี่หลัก: พ.ศ. ↔ ค.ศ. ต่างกัน 543 ปี ตรวจศักราชที่ระบุจริงและวันในปฏิทิน รวมปีอธิกสุรทิน ไม่ใช้สูตรนี้แทนการตรวจวันที่ประวัติศาสตร์หรือจันทรคติ
- `31/02/2569` เป็นวันที่ไม่มีจริง ให้รอยืนยัน ไม่เลื่อนไปเป็นเดือนมีนาคม
- ปีสั้น เช่น `69`, `70` อาจหมายถึงคนละศักราช/ศตวรรษ ให้เจ้าของเอกสารยืนยันปีเต็ม ไม่เติม 24xx/25xx อัตโนมัติ
- ข้อความที่มีหลายวัน เวลา หรือสถานที่ ให้คงข้อความเดิม แยกข้อมูลจากต้นทางก่อนจัดรูปแบบ ไม่เลือกวันแรกแทนทั้งข้อความ
- รูปแบบที่เสนอ: ฟอร์มตรวจใบเสร็จ `02/10/2569`; ร่างหนังสือ `2 ตุลาคม 2569` แบบหน่วยงานที่ยืนยันแล้วมีลำดับก่อนข้อเสนอนี้
- ใช้ calendar date โดยไม่เลื่อนวันจาก timezone ของเครื่อง ไม่มีการเดาเวลา/เขตเวลาปลายทาง

## รหัสและเลขระบุตัวตน

ไม่แปลงเลขปีที่อยู่ในเลขหนังสือหรือเลขอ้างอิง ไม่ตัดเลขนำหน้า และไม่แก้ checksum ด้วยการสร้างเลขท้ายขึ้นเอง ตัวตรวจ checksum ของ Desktop เป็นการตรวจรูปแบบ ไม่พิสูจน์ว่าร้าน/บุคคลมีอยู่จริงหรือมีสิทธิเบิก

## จำนวนเงินและภาษี

- แยกค่าที่เอกสารระบุออกจากค่าที่คำนวณ การคำนวณไม่เติม VAT ที่เอกสารไม่ได้ระบุ
- เงินที่มีสองตำแหน่งทศนิยมใช้หน่วยสตางค์หรือ decimal arithmetic สำหรับตรวจยอด ห้ามพึ่ง floating-point equality ในการตัดสินความต่างเล็กน้อย
- เมื่อกำหนดอัตราไว้จากแหล่งที่ยืนยัน: ยอดไม่รวม VAT → VAT = ฐาน × อัตรา; ยอดรวม VAT → ฐาน = ยอดรวม ÷ (1 + อัตรา) ระบุฐาน อัตรา แหล่ง และวิธีปัดเศษให้ตรวจย้อนกลับได้
- ตรวจหัก ณ ที่จ่ายเฉพาะเมื่อมีแหล่งยืนยันอัตราและฐานที่ใช้ ไม่เดาประเภทบริการจากชื่อร้าน
- เอกสารที่อ่านได้ไม่ชัดต้องคง `EXTRACTED_UNVERIFIED` และระบุว่าผลคำนวณเป็นการตรวจแบบมีเงื่อนไข ไม่ใช่ `DERIVED_FACT` ที่ยืนยันแล้ว เมื่อค่าต้นทางเป็น `SOURCE_FACT` ที่ตรวจแล้วจึงให้ผลคำนวณเป็น `DERIVED_FACT` พร้อมสูตรและแหล่งได้
- อย่าสับสนหนังสือรับรองการหักภาษี ณ ที่จ่ายกับแบบนำส่ง ภ.ง.ด.3/53 การออกเอกสารและการนำส่งเป็นคนละงาน ต้องส่ง AFP ตรวจข้อกำหนดปัจจุบัน

วิธีการเลือกช่องและรูปแบบดัดแปลงจาก `thai-date-format` / `thai-invoice` ใน Boom-Vitt/claude-thai-skills โดยเขียนใหม่สำหรับ STeP ไม่คัดลอกตัว parser หรือตารางอัตรา ดู [ที่มาและข้อจำกัด](third-party-methods.md)
