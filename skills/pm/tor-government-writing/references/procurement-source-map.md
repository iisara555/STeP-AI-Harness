# Procurement source map: discovery is not approval

แผนที่สำหรับตรวจสาระและหาแหล่งจริง ไม่ใช่กฎพัสดุของ STeP ไม่ยืนยันฉบับล่าสุดหรือการใช้บังคับกับงานใดโดยอัตโนมัติ ตรวจ URL ชื่อฉบับ วัน รุ่น เลขข้อ ขอบเขตการใช้ และฉบับแก้ไข ณ วันร่างทุกครั้ง เก็บผลไว้ใน `document_review`

ลิงก์สาธารณะและการอ่านเอกสารเก่าไม่เปลี่ยนสถานะ source ใน `manifest/documents.yaml` ถ้ามีเอกสารปัจจุบันจากเจ้าของให้ตรวจทะเบียนและความเกี่ยวข้องก่อนใช้ การมีแต่ชื่อกฎหมาย/URL หรือผลค้นหาไม่เท่ากับอ่านเนื้อความแล้ว

## เทียบสาระของแนวทาง TOR แบบละเอียดกับ working outline

ตารางนี้เป็นการสรุปเพื่อช่วยหาเนื้อหา ไม่ใช่การเลือกแนวทางแทนผู้มีหน้าที่ และไม่ทำให้เงื่อนไขที่ขาดกลายเป็นเงื่อนไขมาตรฐาน:

| สาระที่ต้องตรวจจากแหล่ง | ตำแหน่งในโครงทำงาน 16 หัวข้อ |
|---|---|
| เหตุที่จัดหา / เป้าหมาย | 1 / 2 |
| คุณสมบัติผู้เสนอ | 11 |
| รายละเอียดสิ่งที่ซื้อหรือจ้างและเอกสารประกอบ | 7 / 9 |
| กำหนดส่งมอบ | 5 / 13 |
| หลักเกณฑ์คัดเลือก | 12 — แยกจากตรวจรับใน 9 |
| วงเงินจัดสรร | 6 — แยกสถานะจากราคากลาง |
| งวดงานกับการจ่ายเงิน | 7 / 10 |
| ค่าปรับ | 13 |
| การรับประกันเมื่อเกี่ยวข้อง | 14 |

ถ้าใช้แบบหน่วยงานอีกโครง ให้เทียบสาระกับเลขข้อของแบบนั้นแทน หัวข้อเพิ่มเรื่องผู้ใช้ สถานที่ ประโยชน์ สิทธิและผู้รับผิดชอบเป็นส่วนช่วยทำงาน ไม่อ้างว่าเป็นรายการที่กฎหมายบังคับทั้งหมด ระเบียบงานสารบรรณช่วยจัดหนังสือนำส่ง ไม่ยืนยันเงื่อนไขพัสดุใน TOR

## บันทึกที่ต้องมีในผลตรวจ

ชื่อฉบับ/เจ้าของ → URL หรือไฟล์และตำแหน่งข้อความ → รุ่น/วันมีผล → วันที่เปิดตรวจ → ใช้กับงานนี้เพราะอะไร → สถานะ `อ่านแล้ว / เปิดไม่ได้ / รอยืนยันความปัจจุบัน / ขัดกัน` → ข้อใน TOR ที่ได้รับผล

เงื่อนไขที่ต้องพึ่งแหล่งยังไม่พร้อมให้ระบุ `NEED-SOURCE` พร้อมเจ้าของคำตอบ ร่างเหตุผล ขอบเขตที่เสนอ และวิธีตรวจเชิงหน้าที่ต่อได้ ไม่อ้างเลขมาตรา อัตรา ระยะเวลา คุณสมบัติ หรือคะแนนจากความจำ และไม่เลือกกฎที่ขัดกันเอง
