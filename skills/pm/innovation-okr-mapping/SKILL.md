# STeP Innovation OKR Mapping Engine

## Purpose

แปลงเป้าหมายยุทธศาสตร์ของกระทรวง อว. มหาวิทยาลัยเชียงใหม่ และ STeP ให้เป็น **Objectives & Key Results ระดับไตรมาสของแต่ละทีม** ที่วัดผลสัมฤทธิ์ได้จริง ไม่ติดกับดักการนับจำนวนกิจกรรม (Output Trap)

ใช้กับฝ่ายยุทธศาสตร์ (SIT), ระบบคุณภาพ (QS) และบริหารนวัตกรรม (IMO)

## เมื่อควรใช้

ใช้เมื่อผู้ใช้พูดในลักษณะ:
- "ช่วยตั้ง OKR ของทีมไตรมาสนี้"
- "แปลงเป้าหมายองค์กรเป็นตัวชี้วัดของทีม"
- "ทบทวน KR ที่ตั้งไว้ว่าวัดผลลัพธ์จริงไหม"

**Anti-trigger:**
- ต้องการติดตามงานประจำสัปดาห์ ให้ใช้ `team-weekly-review`
- ต้องการทบทวน KPI ของระบบคุณภาพตาม ISO ให้ใช้ `quality-objective-kpi-review`
- ต้องการรายงานสถานะต่อผู้บริหาร ให้ใช้ `executive-status-update`

## Inputs

ขั้นต่ำ:
- เป้าหมายระดับองค์กรหรือแผนยุทธศาสตร์ของปีงบประมาณ
- ทีมและขอบเขตงานที่จะตั้ง OKR

ช่วยให้ผลแม่นขึ้นถ้ามี:
- ค่า Baseline จากไตรมาสหรือปีก่อน
- ข้อจำกัดด้านทรัพยากรที่ทราบแล้ว

ถ้าไม่มี Baseline ให้ระบุว่า `[รอยืนยัน]` อย่าประมาณค่าขึ้นเอง

## Source

- เป้าหมายยุทธศาสตร์ต้อง resolve จากแผนที่ประกาศจริง ไม่ใช้ความจำ ดู `manifest/documents.yaml` และ OIT O5 ใน `docs/step-public-profile.md`
- ค่า Baseline และ Actual ต้องอ้างอิงระบบฐานข้อมูลหรือรายงานที่ตรวจสอบย้อนได้
- แม่แบบในโฟลเดอร์นี้: `templates/okr-worksheet-template.md`

## Workflow

1. **กำหนดทิศทาง** — ทบทวนเป้าหมายปีงบประมาณของ STeP, RSP North และกระทรวง อว. แล้วระบุโฟกัสหลักของไตรมาส
2. **ร่าง Objective** — เขียนเป้าหมายเชิงคุณภาพ 1-2 ข้อ สั้นและชัดว่าทำไมสิ่งนี้สำคัญที่สุดในไตรมาสนี้
3. **กำหนด 3 Key Results** ตาม `templates/okr-worksheet-template.md`
   - KR1 ผลลัพธ์ปลายทาง เช่น มูลค่าเงินลงทุนที่ระดมได้
   - KR2 คุณภาพและการยกระดับ เช่น การยกระดับ TRL
   - KR3 ประสิทธิภาพการดำเนินงาน เช่น อัตราการใช้งานเครื่องจักร
   - ทุก KR ระบุ Baseline, Target และ Confidence
4. **แตกแผนรายสัปดาห์** — แปลง KR เป็น Key Initiatives เพื่อส่งต่อให้ `team-weekly-review` ติดตาม

## Output

- ใบงาน OKR รายไตรมาส: Objective, KR 3 ข้อพร้อม Baseline / Target / Confidence
- คำอธิบายว่าแต่ละ KR เชื่อมกับ North Star Metric ขององค์กรอย่างไร
- รายการ Key Initiatives รายสัปดาห์
- รายการข้อมูลที่ยังไม่มี Baseline ติดป้าย `[รอยืนยัน]`

## Authority

AI ช่วยได้: ยกร่าง Objective และ KR ตรวจว่า KR วัดผลลัพธ์หรือแค่กิจกรรม และเสนอ Initiative

ต้องให้มนุษย์ตัดสิน:
- การรับรอง OKR ของทีมและการผูกกับการจัดสรรทรัพยากร
- การประเมินผลการปฏิบัติงานรายบุคคลจากผล OKR — `hr-performance-evaluation` เป็น human-only
- การเปลี่ยนเป้าหมายระดับองค์กร

## Handoff

- Key Initiatives ส่งต่อ `team-weekly-review` เพื่อติดตามรายสัปดาห์
- ความคืบหน้าที่ต้องรายงานผู้บริหาร ส่งต่อ `executive-status-update`
- KR ที่ผูกกับระบบคุณภาพ ส่งต่อ `quality-objective-kpi-review`

พร้อมส่งต่อเมื่อ: ทุก KR มี Baseline, Target, Confidence และเจ้าของ KR ชัดเจน

## Guardrails

1. **Outcome over Output** — KR ต้องเป็นการเปลี่ยนแปลงที่เกิดขึ้นจริง ไม่ใช่รายการกิจกรรม เช่น "จัดสัมมนา 1 ครั้ง" ไม่ใช่ KR
2. **เชื่อมกับ North Star** — ทุกเป้าหมายระดับทีมต้องอธิบายได้ว่าขับเคลื่อนตัวชี้วัดหลักขององค์กรอย่างไร
3. **Stretch but Achievable** — ความสำเร็จราว 70% ถือว่าเป็นการตั้งเป้าที่ท้าทายอย่างเหมาะสม
4. **ตัวเลขต้องตรวจสอบได้** — Baseline และ Actual ต้องมีแหล่งอ้างอิง ห้ามสร้างสถิติขึ้นเอง
5. **ไม่ใช้ OKR ตัดสินรายบุคคลโดยอัตโนมัติ** — การประเมินผลบุคคลเป็นอำนาจของ HD
