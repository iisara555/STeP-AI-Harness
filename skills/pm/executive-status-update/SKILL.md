# STeP Executive Status Update Engine

## Purpose

สังเคราะห์ความคืบหน้าของโครงการเดี่ยวหรือพอร์ตโฟลิโอหลายโครงการ ให้เป็น **รายงานสรุปสำหรับผู้บริหารและคณะกรรมการ** ที่อ่านเร็ว ตรงประเด็น และชี้ชัดว่าผู้บริหารต้องตัดสินใจอะไรเพื่อปลดล็อกคอขวด

ใช้กับฝ่ายยุทธศาสตร์ (SIT), บริหารนวัตกรรม (IMO), เครือข่าย อว. (NMCO) และหัวหน้าโครงการ (PM)

## เมื่อควรใช้

ใช้เมื่อผู้ใช้พูดในลักษณะ:
- "สรุปสถานะโครงการให้ผู้บริหาร"
- "ทำรายงานเข้าบอร์ด / เข้าที่ประชุมผู้บริหาร"
- "รวมสถานะหลายโครงการเป็นหน้าเดียว"

**Anti-trigger:**
- ต้องการสร้างหรือแก้แผนงาน ให้ใช้ `project-plan`
- ต้องการสรุปบันทึกประชุมเป็น action ให้ใช้ `meeting-summary`
- ต้องการติดตามงานประจำสัปดาห์ของทีม ให้ใช้ `team-weekly-review`

## Inputs

ขั้นต่ำ:
- ข้อมูลความคืบหน้าของโครงการ เช่น บันทึกประชุม WBS หรือรายงานรายสัปดาห์
- กำหนดส่งมอบตามแผนที่ใช้เทียบ

ช่วยให้รายงานแม่นขึ้นถ้ามี:
- สถานะการเบิกจ่ายและงวดเงินที่ยืนยันแล้ว
- ประเด็นข้ามทีมที่ค้างอยู่ (AFP, LES, GA)

ตัวเลขที่ไม่มีหลักฐานให้ระบุ `[รอยืนยัน]` ห้ามประมาณเปอร์เซ็นต์ความคืบหน้าเอง

## Source

- แหล่งหลักคือ **เอกสารความคืบหน้าที่ผู้ใช้ให้มา**
- ตัวเลขการเบิกจ่ายต้องมาจากข้อมูลที่ AFP หรือเจ้าของโครงการยืนยัน ไม่ใช่การคำนวณเอง
- แม่แบบในโฟลเดอร์นี้: `templates/sbnr-status-template.md`

## Workflow

1. **Data Intake** — รวบรวมความคืบหน้าจากบันทึกประชุม WBS หรือรายงานรายสัปดาห์ แล้วเทียบกับ Milestone ในแผน
2. **Traffic-Light Triage** — ประเมินสถานะแต่ละโครงการ
   - **Green (On Track):** ดำเนินการตามแผน ผลผลิตครบตามเกณฑ์
   - **Yellow (At Risk):** ล่าช้าไม่เกิน 15-30 วัน หรือมีคอขวดเอกสาร แต่ทีมมีแผนแก้ไขชัดเจน
   - **Red (Blocked / Critical):** ติดขัดรุนแรง กระทบระเบียบการเงิน เสี่ยงผิดสัญญา หรือผู้รับจ้างส่งงานไม่ได้
3. **Synthesize SBNR** ตาม `templates/sbnr-status-template.md`
   - **S — Status:** ผลงานสำคัญที่เสร็จในรอบที่ผ่านมา 1-2 ข้อ
   - **B — Blockers:** ปัญหาที่ทำให้งานชะลอ โดยเฉพาะจุดเชื่อมข้ามทีม
   - **N — Next Steps:** งานที่จะส่งมอบใน 2 สัปดาห์ถัดไป
   - **R — Risks & Asks:** ความเสี่ยงและสิ่งที่ขอให้ผู้บริหารอนุมัติหรือประสาน
4. **Executive Action Summary** — ยกประเด็นที่ต้องตัดสินใจขึ้นหน้าแรก พร้อมกรอบเวลาและผลกระทบหากล่าช้า

## Output

- ตารางสถานะพอร์ตโฟลิโอพร้อมระดับ Green / Yellow / Red และเหตุผลกำกับ
- เนื้อหา SBNR ต่อโครงการ
- ตารางสรุปสิ่งที่ผู้บริหารต้องอนุมัติ ตัดสินใจ หรือประสานงาน พร้อมกำหนดเวลา
- ข้อมูลที่ยังไม่ยืนยันแยกเป็นรายการ `[รอยืนยัน]`

## Authority

AI ช่วยได้: จัดโครงสร้างรายงาน ประเมินระดับสัญญาณตามเกณฑ์ที่ระบุ และร่างข้อเสนอให้ผู้บริหารพิจารณา

ต้องให้มนุษย์ตัดสิน:
- การอนุมัติขยายเวลางวดงานหรือปรับวงเงิน — `budget-allocation`
- การตัดสินใจเชิงนโยบายและการสั่งการข้ามฝ่าย
- การรับรองตัวเลขการเบิกจ่ายก่อนนำเข้าที่ประชุม

## Handoff

- ประเด็นที่ต้องแก้ที่แผนงาน ส่งกลับ `project-plan`
- คอขวดด้านจัดซื้อและการเงิน ส่งต่อ AFP
- ประเด็นที่ต้องให้ผู้บริหารที่กำกับทีมตัดสิน ดูผู้รับผิดชอบที่ `manifest/organization.yaml` → `executiveOversight`

พร้อมส่งต่อเมื่อ: ทุกสถานะมีเหตุผลกำกับ และทุก Ask ระบุผู้อนุมัติกับกรอบเวลาแล้ว

## Guardrails

1. **ห้ามรายงานแบบแตงโม** — ข้างนอกเขียวข้างในแดงไม่ได้ ถ้ามีคอขวดหรือเสี่ยงไม่ทันกำหนด ต้องขึ้น Yellow หรือ Red ตรงไปตรงมา
2. **ครบ SBNR เสมอ** — ขาดข้อใดข้อหนึ่งถือว่ารายงานยังไม่สมบูรณ์
3. **จบด้วยสิ่งที่ผู้บริหารต้องทำ** — ระบุว่าต้องอนุมัติ ตัดสินใจ หรือประสานกับใคร พร้อมผลกระทบหากล่าช้า
4. **ไม่กุตัวเลข** — เปอร์เซ็นต์ความคืบหน้าและยอดเบิกจ่ายต้องมีหลักฐาน
5. **ไม่ระบุความผิดรายบุคคล** — อธิบายคอขวดเชิงกระบวนการ ไม่ใช่ชี้ตัวผู้รับผิด
