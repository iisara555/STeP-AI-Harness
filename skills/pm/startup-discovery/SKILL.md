# STeP Startup Discovery Engine

## Purpose

โค้ชผู้ประกอบการและนักวิจัยให้ตรวจสอบว่าเทคโนโลยีหรือผลิตภัณฑ์ที่พัฒนาขึ้น **มีตลาดจริงและตอบปัญหาลูกค้าจริง (Problem-Solution Fit)** ก่อนทุ่มงบประมาณและเวลาสร้างต้นแบบระดับอุตสาหกรรม

ใช้กับทีมบ่มเพาะธุรกิจนวัตกรรม (PITI), บ่มเพาะสตาร์ทอัพ (ISI), ผู้ประกอบการ (EIC) และการตลาดนวัตกรรม (MI)

## เมื่อควรใช้

ใช้เมื่อผู้ใช้พูดในลักษณะ:
- "ช่วยดูว่างานวิจัยนี้มีตลาดจริงไหม"
- "ทำ Value Proposition Canvas ให้ทีมนี้"
- "เตรียมคำถามสัมภาษณ์ลูกค้า"
- "ควรทดสอบสมมติฐานอะไรก่อน"

**Anti-trigger:**
- ต้องการติดตามทีมหลัง mentoring แล้ว ให้ใช้ Skill ของ ISI
- ต้องการวางแผนโครงการหรืองวดงาน ให้ใช้ `project-plan`
- ต้องการสำรวจสัญญาณตลาดระดับอุตสาหกรรม ให้ใช้ `market-signal-radar`

## Inputs

ขั้นต่ำ:
- เทคโนโลยีหรือผลิตภัณฑ์ที่กำลังพัฒนา
- กลุ่มลูกค้าที่คิดว่าจะเป็นเป้าหมาย

ช่วยให้ผลแม่นขึ้นถ้ามี:
- ผลสัมภาษณ์หรือข้อมูลตลาดที่เคยเก็บไว้
- ต้นทุนการผลิตหรือข้อจำกัดทางเทคนิคที่รู้แล้ว

## Source

- แหล่งหลักคือ **คำบอกเล่าของลูกค้าจากการสัมภาษณ์จริง** ไม่ใช่การคาดเดาของทีม
- ข้อมูลตลาดจากแหล่งสาธารณะใช้เป็น discovery evidence ต้องระบุที่มาและวันที่
- ห้ามเก็บโปรไฟล์รายบุคคลของผู้ให้สัมภาษณ์ถาวร ตาม `docs/knowledge-policy.md`
- แม่แบบในโฟลเดอร์นี้: `templates/value-proposition-canvas-template.md`, `templates/customer-interview-script-template.md`

## Workflow

1. **ยกร่าง VPC** — ระบุกลุ่มลูกค้าเฉพาะกลุ่มแรก (Beachhead) แล้วเติม Customer Jobs / Pains / Gains คู่กับ Products / Pain Relievers / Gain Creators ตาม `templates/value-proposition-canvas-template.md`
2. **Assumption Mapping** — สกัดสมมติฐาน 3 มิติ: Desirability (ลูกค้ามีปัญหานี้จริงไหม), Feasibility (ทีมและแล็บทำได้ตามสเปกไหม), Viability (ต้นทุนถูกพอจะตั้งราคาแข่งได้ไหม) แล้วเลือกข้อที่ "สำคัญสูงสุดแต่ยังไม่มีหลักฐาน" มาทดสอบก่อน
3. **สัมภาษณ์ลูกค้า** — ใช้ `templates/customer-interview-script-template.md` ปรับคำถามตามบริบท แล้วลงพื้นที่สัมภาษณ์กลุ่มเป้าหมายอย่างน้อย 5-10 ราย
4. **สรุปและตัดสินใจ** — สรุปเป็น 3 ทางเลือก
   - **Validated** → เดินหน้าทำ PoC หรือวางแผนใน `project-plan`
   - **Pivot** → ลูกค้ามีปัญหาอื่นสำคัญกว่า ให้ปรับ VPC ใหม่
   - **Kill / Park** → ลูกค้าไม่เห็นความจำเป็นและไม่ยินดีลงทุน ให้หยุดก่อนเสียทรัพยากร

## Output

- Value Proposition Canvas ที่กรอกแล้ว พร้อมระบุว่าข้อใดมีหลักฐานและข้อใดยังเป็นสมมติฐาน
- ตาราง Assumption Map เรียงตามความสำคัญและระดับหลักฐาน
- สคริปต์สัมภาษณ์ที่ปรับตามบริบทโครงการ
- ข้อสรุป Validated / Pivot / Kill พร้อมหลักฐานที่ใช้ตัดสิน

## Authority

AI ช่วยได้: ยกร่าง VPC ตั้งสมมติฐาน เตรียมคำถาม และสังเคราะห์ผลสัมภาษณ์

ต้องให้มนุษย์ตัดสิน:
- การตัดสินใจเดินหน้า Pivot หรือยุติโครงการ
- การอนุมัติงบพัฒนาต้นแบบ — `budget-allocation`
- การรับทีมเข้าโปรแกรมบ่มเพาะ

AI ไม่สรุปแทนว่าตลาดมีจริง ถ้ายังไม่มีผลสัมภาษณ์รองรับ

## Handoff

- ผล Validated ส่งต่อ `project-plan` เพื่อวางแผน PoC
- สมมติฐานด้านเทคนิคที่ต้องทดสอบในแล็บ ส่งต่อ LES หรือ FOODFABR
- ประเด็นทรัพย์สินทางปัญญา ส่งต่อ Tech Spin

พร้อมส่งต่อเมื่อ: สมมติฐานสำคัญที่สุดได้รับการทดสอบกับลูกค้าจริงแล้ว และข้อสรุปอ้างอิงคำบอกเล่าที่บันทึกไว้ได้

## Guardrails

1. **ยึดพฤติกรรมจริงในอดีต** — ถามว่า "ปัจจุบันแก้ปัญหานี้อย่างไร เสียเงินหรือเวลาเท่าใด" ไม่ถามคำถามสมมติแบบ "ถ้าเราทำสิ่งนี้คุณจะใช้ไหม" ตามหลัก The Mom Test
2. **Value Proposition Fit ต้องมีหลักฐาน** — Pain Reliever / Gain Creator ต้องจับคู่กับ Pain / Gain จริงอย่างน้อย 1-2 ข้อหลัก
3. **No Solution Bias** — มองจาก Market Pull ควบคู่ Technology Push อย่ายึดติดเทคโนโลยีของตัวเอง
4. **รายงานตามจริง** — ถ้าลูกค้าไม่สนใจหรือไม่ยินดีจ่าย ต้องรายงานตรงไปตรงมาเพื่อ Pivot ห้ามแต่งผลสำรวจเพื่อขอผ่านทุน
5. **ไม่ขายระหว่างสัมภาษณ์** — เน้นเรียนรู้ขั้นตอนการทำงานจริงและมูลค่าความเสียหายที่เคยเกิด
