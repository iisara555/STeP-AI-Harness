# Lane Contract — โครงสร้างตาราง Run of Show

อ้างจาก Skill `event-run-of-show` ใช้เมื่อต้องแตกคิวหรืออ่าน sequence เดิมให้เข้าโครงเดียวกัน

## 1. เอกสารนี้คืออะไร

Run of Show ไม่ใช่กำหนดการ กำหนดการบอกว่าช่วงไหนมีอะไร Run of Show บอกว่า **ใครทำอะไรในวินาทีไหน และจอกับเสียงต้องเป็นอย่างไรตอนนั้น**

หลักสามข้อที่ทำให้ตารางนี้ใช้งานได้จริง:

1. **หนึ่งแถว = หนึ่ง cue** ไม่ใช่หนึ่งวาระ วาระคือแถวหัวข้อที่ถือ duration รวม
2. **เวลาสองระดับ บวกนาฬิกาที่สาม** — `Block Time` ครอบ `Cue Time` และ `Timer` คือเลขที่ผู้พูดเห็น ซึ่งเป็นคนละค่ากับความยาวคิว
3. **ห้าม merged cell** — เติมค่า `Block` ซ้ำทุกแถว เพราะเหตุผลทั้งหมดของตารางนี้คือการกรองดูเฉพาะ lane ของตัวเอง ถ้าเซลล์ว่างแปลว่า "เหมือนแถวบน" การกรองจะพัง

## 2. ใครอ่าน lane ไหน

| บทบาท | อ่านคอลัมน์ |
| --- | --- |
| พิธีกร / MC | `Cue Time`, `Cue`, `Timer` |
| Show caller | `Block`, `Cue No.`, `Cue Time`, `Cue Duration`, `Lead` |
| ทีมจอ / VDO | `Format / Scene`, `Screen L`, `Screen Main`, `Screen R`, `Asset Link` |
| ทีมเสียง | `Sound`, `Timer` |
| ทีมแสง | `Light`, `Format / Scene` |
| ทีมเวที | `Facilities (ของที่ต้องมี)`, `Set Change (สิ่งที่ต้องทำ)` |
| ผู้พูด | `Monitor` |
| PM | `Lead`, `Support`, `Status`, `Remark / Checklist` |

lane ไหนไม่มีคนอ่านในงานนี้ ให้ลบทิ้ง

## 3. คอลัมน์

### บังคับทุกงาน

| # | คอลัมน์ | กติกา |
| --- | --- | --- |
| 1 | `Day` | `D-1` / `D0` / `Day 1` / `Day 2` / `Teardown` งานเตรียมก่อนวันงานและงานเก็บอยู่ในตารางเดียวกัน |
| 2 | `Date` | `YYYY-MM-DD` ถ้าต้นทางเป็น พ.ศ. ให้แปลงแล้วเก็บของเดิมไว้ใน `Remark` |
| 3 | `Block No.` | จำนวนเต็ม เรียงต่อเนื่องภายในหนึ่ง `Day` |
| 4 | `Block` | ชื่อวาระ เติมซ้ำทุกแถว |
| 5 | `Block Time` | `HH:MM–HH:MM` แบบ 24 ชั่วโมง |
| 6 | `Block Duration (นาที)` | จำนวนเต็ม **ตามที่ต้นทางระบุ** เก็บไว้แม้จะไม่ตรงกับผลรวม เพราะส่วนต่างคือสิ่งที่ต้องรายงาน |
| 7 | `Cue No.` | รูปแบบ `B03-C04` |
| 8 | `Cue Time` | `HH:MM–HH:MM` หรือ `HH:MM` สำหรับคิวชั่วขณะ |
| 9 | `Cue Duration (นาที)` | คำนวณจาก `Cue Time` ติดป้าย `DERIVED_FACT` |
| 10 | `Cue` | ประโยคที่ show caller เรียกได้ หนึ่ง action ต่อแถว |
| 11 | `Lead` | **หนึ่งคนหรือหนึ่งบทบาทเท่านั้น** ว่างไม่ได้ |
| 12 | `Status` | `ยืนยันแล้ว` / `รอยืนยัน` / `ร่าง` / `ยกเลิก` |
| 13 | `Provenance` | หนึ่งใน 6 label มาตรฐาน |

### ตามงาน — ใส่เมื่อมีจริงเท่านั้น

| คอลัมน์ | กติกา |
| --- | --- |
| `Timer (นาที)` | เลขที่ผู้พูดเห็น ต้องไม่เกิน `Cue Duration` ถ้าตั้งใจให้สั้นกว่าเพื่อกันเวลา ต้องเขียนเหตุผลใน `Remark` |
| `Format / Scene` | รหัสฉากที่ตกลงกับทีม AV ดู `templates/cue-enums-template.md` |
| `Screen L` / `Screen Main` / `Screen R` | ค่าที่ขึ้นแต่ละจอ |
| `Monitor` | จอที่ผู้พูดเห็น เช่น เวลานับถอยหลังและสถานะ Present |
| `Sound` | เพลง เอฟเฟกต์ ไมค์ |
| `Light` | สถานะไฟเวทีและไฟห้อง |
| `Facilities (ของที่ต้องมี)` | ไมค์ โพเดียม clicker น้ำดื่ม |
| `Set Change (สิ่งที่ต้องทำ)` | คำสั่งเปลี่ยนฉาก เช่น เอาโพเดียมลง ยกโต๊ะขึ้น |
| `Asset Link` | ลิงก์สไลด์หรือ VTR ของคิวนั้น |
| `Support` | `ชื่อ : งานย่อย` บรรทัดละคน |
| `Zone / Room` | โซนหรือห้องเมื่องานมีหลายพื้นที่ |
| `Remark / Checklist` | หมายเหตุและของที่ต้องเตรียม |

### ตัดออกโดยตั้งใจ

`Contact` — เบอร์โทร ทะเบียนรถ และเลขเที่ยวบิน **ไม่อยู่ในตารางนี้** ตารางนี้ถูกส่งต่อให้ทีมงานหลายสิบคนและถูกคัดลอกไปใช้งานถัดไป ให้เก็บข้อมูลติดต่อไว้ในรายชื่อผู้ประสานงานที่คุมสิทธิ์แยกต่างหาก แล้วอ้างถึงด้วยชื่อหรือบทบาทเท่านั้น

## 4. โมเดลเวลา

```text
Block Time   08:30–08:40   Block Duration 10 นาที
  |
  +-- Cue 08:30–08:33   Cue Duration 3    Timer (ไม่มี)
  +-- Cue 08:33–08:35   Cue Duration 2    Timer (ไม่มี)
  +-- Cue 08:35–08:40   Cue Duration 5    Timer 4  <- ตั้งใจให้สั้นกว่า ต้องเขียนเหตุผล
```

ตรวจสามอย่างเสมอ:
- ผลรวม `Cue Duration` ในหนึ่ง block เทียบกับ `Block Duration` ที่ต้นทางระบุ
- ทุก `Cue Time` ต้องอยู่ในกรอบ `Block Time`
- `Timer` ต้องไม่เกิน `Cue Duration` **เกินเมื่อไรคือบั๊ก ไม่ใช่สไตล์การเขียน**

## 5. อะตอมของพิธีกร

คิวบนเวทีแตกเป็นหน่วยย่อยแบบนี้ แถวละหนึ่งอัน:

```text
MC เชื่อม -> MC เชิญ -> วิทยากรขึ้นเวที -> เนื้อหา -> MC ขอบคุณ -> ลงเวที
```

ช่วงเนื้อหาคือช่วงเดียวที่ควรมี `Timer` ส่วนช่วงเชื่อมและเชิญมักใช้เวลา 2 ถึง 3 นาที ซึ่งเป็น `PLANNING_ASSUMPTION` จนกว่าจะซ้อมจริง

## 6. Forward-fill

เมื่ออ่าน sequence เดิมที่ใช้ merged cell ให้เติมค่าลงมาตามลำดับนี้: `Day`, `Date`, `Block No.`, `Block`, `Block Time`

ถ้าเติมแล้วได้ผลกำกวม เช่น คิวอยู่ระหว่าง block สองอัน ให้ขึ้นเป็น finding อย่าเลือกข้างเอง

## 7. Provenance

| ค่า | label |
| --- | --- |
| เวลา ชื่อ สถานที่ ที่ยืนยันแล้วจากต้นทาง | `SOURCE_FACT` |
| `Cue Duration` และผลรวมที่คำนวณได้ | `DERIVED_FACT` |
| สิ่งที่ผู้ใช้พิมพ์บอกในแชท | `USER_INPUT` |
| การแตกคิวที่เสนอ บทเชื่อม เวลาที่เสนอ คิวสำรอง | `PLANNING_ASSUMPTION` |
| กติกา "ทุกคิวต้องมี Lead" และ enum `Status` | `ORGANIZATION_RULE` |
| ความหมายรหัส Scene ที่เสนอ และช่วงเวลาซ้อมที่แนะนำ | `AI_RECOMMENDATION` |

6 label นี้ปิดตายตาม `manifest/provenance.yaml` ห้ามเพิ่ม label ที่เจ็ด
