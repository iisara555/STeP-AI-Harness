# STeP Writing

## Purpose

สร้างหรือปรับข้อความสำหรับการสื่อสารของ STeP จากข้อมูลที่ผู้ใช้หรือแหล่งข้อมูลให้มา

Skill นี้มีหน้าที่:

**Facts / Source → Communication-ready Draft**

โดยปรับภาษา โครงสร้าง น้ำเสียง และระดับรายละเอียดให้เหมาะกับผู้รับสารและช่องทาง

ไม่ใช้ Skill นี้เพื่อค้นหาข้อเท็จจริงที่ไม่มีในต้นทาง หรือตัดสินสถานะ การอนุมัติ และผู้รับผิดชอบแทนผู้ใช้

## Inputs

อาจได้รับ:

* ข้อเท็จจริงหรือ Bullet points
* Draft เดิม
* Meeting output
* Project update
* รายงานหรือเอกสารต้นทาง
* Action items
* ข้อความที่ต้องการเขียนใหม่

พร้อมข้อมูลบริบทเท่าที่มี เช่น:

* ผู้รับสาร
* วัตถุประสงค์
* ช่องทาง
* ระดับความเป็นทางการ
* ความยาว
* ภาษาที่ต้องการ

ภาษาไทยเป็นค่าเริ่มต้นสำหรับงานภายใน STeP เว้นแต่ผู้ใช้ระบุเป็นอย่างอื่น

## Writing Modes

เลือกเฉพาะรูปแบบที่ตรงกับคำขอ เช่น:

* Email
* หนังสือหรือข้อความทางการ
* Internal message
* Report section
* Executive communication
* Announcement
* Caption / Public communication
* Rewrite / Polish

ไม่จำเป็นต้องใช้โครงสร้างเดียวกันทุกประเภท

## Core Workflow

1. ระบุจากคำขอ:

   * ผู้รับสาร
   * วัตถุประสงค์
   * ช่องทาง
   * ระดับความเป็นทางการ

2. แยกข้อมูลต้นทางเป็น:

   * ข้อเท็จจริงที่ยืนยันได้
   * Action หรือ Request ที่ระบุไว้
   * ข้อมูลที่ยังไม่ยืนยัน

3. รักษาข้อมูลสำคัญตามต้นฉบับ เช่น:

   * ชื่อบุคคล
   * ชื่อหน่วยงาน
   * ชื่อโครงการ
   * วันที่
   * จำนวนเงิน
   * ตัวเลข
   * รหัส
   * ผู้รับผิดชอบ
   * สถานะ
   * การอนุมัติ

4. เลือกโครงสร้างที่เหมาะกับช่องทาง ไม่บังคับ Template เดียวกับทุกงาน

5. ปรับภาษาให้:

   * ชัดเจน
   * กระชับ
   * อ่านง่าย
   * เหมาะกับผู้รับสาร
   * ไม่เพิ่มความหมายเกินต้นทาง

6. ตรวจว่า Draft สุดท้ายไม่มีข้อเท็จจริงใหม่ที่ไม่ได้รับการรองรับ

## Writing Principles

### สำคัญก่อน

หากเป็นข้อความที่มี Action, Decision หรือ Deadline ให้ทำให้สิ่งสำคัญมองเห็นได้เร็ว

แต่ไม่จำเป็นต้องขึ้นต้นด้วย Action ในทุกกรณี เช่น Caption หรือข้อความประชาสัมพันธ์

### เขียนตามผู้รับสาร

ปรับระดับรายละเอียดและศัพท์ตามกลุ่ม เช่น:

* ผู้บริหาร
* พนักงาน STeP
* ผู้ประกอบการ
* Partner
* หน่วยงานภาครัฐ
* บุคคลทั่วไป

### รักษาความหมาย

การ Rewrite หรือ Polish สามารถเปลี่ยน:

* ลำดับ
* ประโยค
* น้ำเสียง
* ความกระชับ

แต่ห้ามเปลี่ยน:

* ข้อเท็จจริง
* สถานะ
* ความรับผิดชอบ
* Deadline
* Approval
* Commitment

## Uncertainty

หากต้นทางมีข้อมูลที่ไม่ชัดเจน:

* อย่าเติมเอง
* ใช้ถ้อยคำที่ไม่ทำให้สิ่งที่ยังไม่ยืนยันกลายเป็นข้อเท็จจริง
* หากข้อมูลนั้นจำเป็นต่อข้อความ ให้ทำเครื่องหมายไว้เพื่อยืนยัน

ตัวอย่าง:

`[รอยืนยันวันที่]`

หรือแยกไว้ในส่วนข้อมูลที่ต้องยืนยันเมื่อเหมาะสม

## Rules

* ห้ามสร้างชื่อ วันที่ ตัวเลข หรือรายละเอียดขึ้นเอง
* ห้ามกำหนด Owner หากต้นทางไม่ได้ระบุ
* ห้ามเปลี่ยน Proposal ให้กลายเป็น Decision
* ห้ามเปลี่ยน Planned ให้กลายเป็น Completed
* ห้ามเขียนเหมือนมีการอนุมัติแล้ว หากยังไม่มีหลักฐาน
* ห้ามสร้าง Commitment ในนาม STeP โดยไม่มีข้อมูลรองรับ
* ห้ามทำให้สมมติฐานดูเป็นข้อเท็จจริง
* รักษาคำเฉพาะ ชื่อโครงการ และรหัสสำคัญตามต้นทาง
* หลีกเลี่ยงภาษาราชการที่ซับซ้อนเกินความจำเป็น เว้นแต่รูปแบบเอกสารกำหนด

เมื่อต้องใช้กฎองค์กรเพิ่มเติม ให้ปฏิบัติตาม:

* `rules/step-writing.md`
* `rules/data-classification.md`
* `rules/human-approval.md`

หากกฎเหล่านี้ขัดกับคำขอ ให้ถือกฎที่มี Authority สูงกว่าเป็นหลัก

## Output

ส่งข้อความที่พร้อมนำไปใช้ต่อเป็นผลลัพธ์หลัก

ไม่ต้องอธิบายกระบวนการเขียน เว้นแต่ผู้ใช้ขอ

หากมีข้อมูลที่จำเป็นแต่ยังไม่ยืนยัน ให้เพิ่มท้ายผลลัพธ์เฉพาะรายการที่เกี่ยวข้อง:

### ข้อมูลที่ต้องยืนยัน

* ...

หากไม่มีข้อมูลค้าง ไม่ต้องสร้างส่วนนี้
