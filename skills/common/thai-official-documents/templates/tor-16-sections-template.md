# Working template — ขอบเขตของงาน ๑๖ หัวข้อ (TOR)

แม่แบบกลางเพื่อร่างพิจารณา ไม่ใช่แบบจัดซื้อจัดจ้างของหน่วยงานฉบับปัจจุบันที่รับรองแล้ว ใช้ร่วมกับ `tor-government-writing` สำหรับสาระและ Source Gate และ `thai-official-documents` สำหรับรูปแบบ ไม่ถือแม่แบบนี้เป็นแหล่งข้อกฎหมายหรือเงื่อนไขสัญญา

ใช้แบบหน่วยงานที่ตรวจแหล่ง รุ่น วันที่ และอำนาจได้ก่อน working template นี้ ข้อกำหนดที่เปลี่ยนได้ เช่น ค่าปรับ คุณสมบัติ วิธีจัดซื้อ งวดเงิน ระยะเวลาและ SLA ต้อง resolve จาก source ปัจจุบัน หากยังไม่มีหรือขัดกันให้คง `[รอยืนยัน: ชื่อช่อง]` พร้อมเจ้าของคำตอบ ห้ามนำความจำของโมเดลหรือข้อความตัวอย่างมาเติมเป็นเงื่อนไขบังคับ

## การจัดหน้าเป็นร่าง

A4 ขอบซ้าย ๓ ซม. ขวา ๒ ซม. บน ๒.๕ ซม. ล่าง ๒ ซม.; ฟอนต์ทำงาน `TH Sarabun PSK` ๑๖ pt ชื่อร่าง ๑๘ pt กึ่งกลาง หัวข้อหลัก ๑๖ pt ตัวหนาและอยู่กับเนื้อหาถัดไป เนื้อความย่อหน้า ๒.๕ ซม. ตารางคงโครงสร้างแก้ไขได้และหัวตารางต่อเนื่อง มีเลขหน้า ตรวจฟอนต์จริงและภาพทุกหน้าก่อนให้สถานะผ่านด้านรูปแบบ `TH Sarabun New` เป็นอีก family หากแบบหน่วยงานกำหนดต้องเลือกอย่างชัดเจน ไม่ถือว่าเทียบเท่ากันโดยอัตโนมัติ ไม่เติมตราครุฑหรือผู้ลงนามให้ TOR โดยอัตโนมัติ

[รอยืนยัน: ชื่อโครงการและประเภทงานซื้อหรือจ้างจากต้นทาง]
[รอยืนยัน: หน่วยงานเจ้าของเรื่อง]
[รอยืนยัน: ปีงบประมาณจากหลักฐาน]

๑. หลักการและเหตุผล
[รอยืนยัน: ความจำเป็นและหลักฐานต้นเรื่อง]

๒. วัตถุประสงค์
[รอยืนยัน: วัตถุประสงค์จากเจ้าของเรื่อง]

๓. กลุ่มเป้าหมายและผู้มีส่วนได้ส่วนเสีย
[รอยืนยัน: กลุ่มและจำนวนที่มีหลักฐาน]

๔. สถานที่ส่งมอบและติดตั้ง / พื้นที่ดำเนินการ
[รอยืนยัน: สถานที่และข้อจำกัดจากต้นทาง]

๕. ระยะเวลาดำเนินโครงการ / ระยะเวลาส่งมอบ
[รอยืนยัน: ระยะเวลาและจุดเริ่มนับตามแหล่งที่ตรวจแล้ว]

๖. วงเงินงบประมาณและราคากลาง
[รอยืนยัน: วงเงิน แหล่งงบ ราคากลาง และสถานะอนุมัติตามหลักฐาน]

๗. ผลผลิตและรายการส่งมอบ (Deliverables)
[รอยืนยัน: รายการ ผลผลิต จำนวน และรูปแบบส่งมอบจากต้นทาง]

๘. ผลลัพธ์และประโยชน์ที่คาดว่าจะได้รับ
[รอยืนยัน: ผลที่คาดและวิธีประเมิน ไม่ใช่ผลที่รับรองแล้ว]

๙. คุณลักษณะเฉพาะของพัสดุ / ขอบเขตของงานและวิธีดำเนินงาน
[รอยืนยัน: สมรรถนะ ขอบเขต และเกณฑ์ตรวจรับที่มีแหล่ง]

๑๐. เงื่อนไขการจ่ายเงินงบประมาณ
[รอยืนยัน: งวดงาน งวดเงิน เงื่อนไข และแหล่งที่มีอำนาจ]

๑๑. คุณสมบัติของผู้ยื่นข้อเสนอ
[รอยืนยัน: คุณสมบัติ เหตุผล และเกณฑ์ปัจจุบันที่ตรวจแหล่งแล้ว]

๑๒. วิธีการจัดซื้อจัดจ้างและหลักเกณฑ์ในการพิจารณาข้อเสนอ
[รอยืนยัน: วิธีจัดซื้อ เกณฑ์พิจารณา ข้อกฎหมายและอำนาจจากแหล่งปัจจุบัน]

๑๓. เงื่อนไขการส่งมอบและอัตราค่าปรับ
[รอยืนยัน: เงื่อนไข อัตราค่าปรับ ฐานคำนวณ และแหล่งฉบับที่ใช้]

๑๔. การรับประกันความชำรุดบกพร่องและระดับการให้บริการ (SLA)
[รอยืนยัน: ระยะรับประกัน วันตอบสนอง วิธีแก้ไข และ SLA จากหลักฐาน]

๑๕. สิ่งที่หน่วยงานจัดเตรียมให้ และข้อกำหนดด้านทรัพย์สินทางปัญญา
[รอยืนยัน: สิ่งที่จัดเตรียม สิทธิ์ และเงื่อนไขตามแหล่งที่ตรวจแล้ว]

๑๖. หน่วยงานผู้รับผิดชอบ
[รอยืนยัน: หน่วยงาน ผู้ประสาน และช่องทางติดต่อจากต้นทาง]

ใช้หัวข้อเหล่านี้เป็น Markdown headings ในร่างที่ส่งเข้า Desktop เพื่อรักษาโครงสร้างเอกสาร ห้ามคัดคำแนะนำการจัดหน้าหรือ Source Gate เข้าเนื้อหา TOR เป็นข้อบังคับ

## ตรวจข้อมูลและแหล่งที่ขาดก่อนเสนอ — แสดงแยกในผลตรวจ ไม่ส่งออกใน TOR

| หัวข้อ / ค่า | ข้อมูลจากต้นทาง | Provenance | แหล่ง / รุ่น / วันที่ตรวจ | สถานะ | เจ้าของคำตอบ / ขั้นตอนต่อไป |
|---|---|---|---|---|---|
| [รอยืนยัน: หัวข้อ] | [รอยืนยัน: ค่า] | [รอยืนยัน: provenance] | [รอยืนยัน: แหล่ง] | รอยืนยัน | [รอยืนยัน: เจ้าของ] |

แยก USER_INPUT / SOURCE_FACT / DERIVED / RECOMMENDATION; ข้อมูล OCR/AI ที่เป็น EXTRACTED_UNVERIFIED คงสถานะจนมีคนเทียบต้นทาง ไม่ถือ consent หรือการเลือกใช้ร่างเป็นการตรวจข้อเท็จจริง ชื่อผู้ประสานและที่อยู่ต้องมาจากเรื่องนี้ ไม่คัดค่าคงที่ขององค์กรมาแทนโดยไม่ตรวจ

ให้ `tor-review` ตรวจสาระและ source gaps แล้วให้ `thai-official-documents` ตรวจ DOCX ที่ render จริง ไม่อ้างว่าการร่างข้อความผ่านการจัดหน้าหรือกฎหมายแล้ว การอนุมัติวิธีจัดซื้อ งบ ลงนาม และออกเลขเป็น Human Authority
