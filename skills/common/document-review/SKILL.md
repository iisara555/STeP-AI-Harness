# STeP General Document Review

## Purpose

เป็นด่านตรวจ **เอกสารทั่วไปก่อนส่ง** สำหรับทุกทีม เมื่อผู้ใช้ต้องการรู้ว่าเอกสารยังขาดอะไร ขัดกันตรงไหน หรือมีจุดใดที่เจ้าของงานต้องแก้เองก่อนส่งต่อ

Skill นี้ไม่แทนการตรวจเฉพาะทางด้าน TOR/จัดซื้อ หนังสือราชการ Privacy ใบเสร็จ ผล Lab หรือ Controlled QMS document

## เมื่อควรใช้

ใช้เมื่อผู้ใช้พูดในลักษณะ:
- “ช่วยตรวจเอกสารนี้ก่อนส่ง”
- “ดูความครบถ้วนให้หน่อย”
- “มีอะไรที่ฉันต้องแก้เองก่อนส่งไหม”
- “ช่วยเช็กวันที่ ตัวเลข ชื่อ หรือข้อมูลที่ขัดกันในเอกสารนี้”

**Anti-trigger:** ถ้ารู้ชัดว่าเป็น TOR, หนังสือราชการ, ใบเสร็จ, ผลทดสอบ Lab, เอกสาร Privacy/PII หรือ Controlled QMS document ให้ handoff ไป Skill เฉพาะทางแทน

## Inputs

ขั้นต่ำ:
- เอกสารหรือข้อความที่ต้องตรวจ
- ผู้รับ/วัตถุประสงค์ ถ้าความเหมาะสมของน้ำเสียงมีผล

ถ้าข้อมูลขาด ให้ตรวจเฉพาะสิ่งที่พิสูจน์ได้จากเอกสาร และระบุ `รอยืนยัน` แทนการเดา

## Source

- แหล่งหลักคือ **เอกสารที่ผู้ใช้ให้มา**
- ถ้าต้องตัดสินตามระเบียบ/นโยบาย/แบบฟอร์ม ให้ resolve Source เฉพาะทางก่อน หรือ handoff ไป Skill ที่มี Source Contract นั้น
- ถ้าไม่มี external authoritative source ที่จำเป็น ให้ระบุว่า `ไม่มี Source ภายนอกที่จำเป็นสำหรับ structural review`

## Workflow

1. **Identify document purpose** — เอกสารนี้จะส่งให้ใคร เพื่ออะไร และคาดหวัง action อะไร
2. **Completeness** — หาหัวข้อ/ข้อมูล/เอกสารแนบ/ผู้รับผิดชอบ/วันครบกำหนดที่กล่าวถึงแต่ยังไม่มี
3. **Internal consistency** — เทียบชื่อ วันที่ ตัวเลข จำนวนเงิน เวอร์ชัน สถานะ และคำเรียกเดียวกันว่าขัดกันเองหรือไม่
4. **Unresolved content** — หา placeholder, TODO, TBD, ช่องว่าง, comment หรือ claim ที่ยังไม่มีหลักฐาน
5. **Audience & tone** — ตรวจว่าระดับภาษาและคำขอตรงกับผู้รับ โดยไม่เปลี่ยนสาระเอง
6. **Specialist detection** — ถ้าเข้าข่ายเอกสารเฉพาะทาง ให้หยุดข้อสรุปเฉพาะด้านและ handoff
7. **Owner action list** — สรุปเฉพาะสิ่งที่เจ้าของเอกสารต้องแก้/ยืนยันเองก่อนส่ง

## Output

ใช้รูปแบบ:

### สรุปก่อนส่ง
- สถานะการตรวจ: ตรวจได้ / ต้องการข้อมูลเพิ่ม / ควรส่งต่อ Skill เฉพาะทาง
- จุดที่ครบและสอดคล้อง:
- จุดที่ขาด:
- จุดที่ขัดกันเอง:
- จุดที่ยังรอยืนยัน:

### สิ่งที่คุณต้องแก้เอง
1. ...
2. ...

### Handoff ที่แนะนำ
- ถ้ามี: Skill ปลายทาง + เหตุผล
- ถ้าไม่มี: `ไม่พบความจำเป็นต้องส่งต่อเฉพาะทางจากข้อมูลที่มี`

## Authority

AI ช่วยตรวจโครงสร้างและความสอดคล้องภายในได้ แต่:
- **ไม่ตัดสินว่าเอกสาร “ผ่าน/ไม่ผ่านระเบียบ”** ถ้ายังไม่ได้ resolve Source ที่เกี่ยวข้อง
- **ไม่รับรองความถูกต้องทางกฎหมาย การเงิน จัดซื้อ QMS หรือวิชาชีพ**
- **ไม่เปลี่ยนข้อความสาระสำคัญเองโดยไม่ให้เจ้าของงานตรวจ**
- การอนุมัติ ลงนาม ส่งจริง หรือรับรองเอกสารเป็นอำนาจของมนุษย์ที่เกี่ยวข้อง

## Handoff

- TOR / งานจัดซื้อ → `tor-review`
- หนังสือราชการ / บันทึกข้อความ → `thai-official-documents`
- PII / Privacy / ข้อมูลลับ → `data-privacy-compliance`
- ใบเสร็จ / หลักฐานเบิก → `receipt-audit`
- ผลทดสอบ / Lab result → `lab-result-review`
- Controlled QMS document / revision / record → `document-record-control`

พร้อมส่งต่อเมื่อระบุได้ว่าเอกสารประเภทใด จุดที่ต้องตรวจเฉพาะทางคืออะไร และมีไฟล์/ข้อมูลต้นทางใดอยู่แล้ว

## Guardrails

- ห้ามแต่งข้อมูลที่เอกสารไม่มีเพื่อทำให้ดู “ครบ”
- วันที่ ตัวเลข ชื่อ หรือ owner ที่ไม่ชัดให้เขียน `รอยืนยัน`
- ไม่ rewrite ทั้งเอกสารโดยอัตโนมัติเมื่อผู้ใช้ขอเพียง “ตรวจ”
- ไม่ใช้ structural review แทน compliance review
- ถ้ามี credential/secret ให้หยุดและใช้กติกาความปลอดภัยก่อนดำเนินการต่อ
