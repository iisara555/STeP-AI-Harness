# เขียน Skill ให้ AI ทำตามได้สม่ำเสมอ

เปิดไฟล์นี้ตอนเขียนหรือตัดแต่งเนื้อหา SKILL.md หรือ description

Skill ที่ดีไม่ได้ทำให้ได้คำตอบเหมือนกันทุกครั้ง แต่ทำให้ AI **ใช้วิธีเดียวกันทุกครั้ง**

## Description คือตัวชี้ ไม่ใช่บทสรุป

- บอก**เงื่อนไขที่ควรใช้**และ**เมื่อไม่ควรใช้** ไม่สรุปขั้นตอนการทำงาน เพราะ AI อาจทำตามบทสรุปแทนการเปิดอ่าน Skill
- ขึ้นต้นด้วยคำที่ผู้ใช้พูดจริง เช่น "ใช้เมื่อมีบันทึกประชุม…" ไม่ใช่ชื่อ methodology
- หนึ่งกรณีใช้หนึ่ง trigger คำพ้องที่หมายถึงเรื่องเดียวกันให้ใส่ใน `manifest/router-index.yaml` ไม่ต้องเขียนซ้ำใน description

## ทุกขั้นตอนต้องมีเกณฑ์ว่าเสร็จ

- เขียนให้ AI แยกได้ว่า "เสร็จ" กับ "ยังไม่เสร็จ" เช่น "ครบเมื่อทุก Action มี Owner หรือเขียนว่า ยังไม่ระบุ" ไม่ใช่ "สรุปให้ครบถ้วน"
- เกณฑ์ที่คลุมเครือทำให้ AI รีบจบขั้นตอนเพื่อไปขั้นถัดไป

## วางเนื้อหาตามความถี่ที่ใช้

1. ขั้นตอนที่ใช้ทุกครั้ง อยู่ใน SKILL.md
2. ข้อมูลอ้างอิงที่ใช้บ่อย อยู่ใน SKILL.md แต่รวมไว้ใต้หัวข้อเดียว
3. สิ่งที่ใช้เฉพาะบางกรณี ย้ายไป `references/` `templates/` หรือ `examples/` แล้วเขียนตัวชี้ที่บอกว่า**เปิดเมื่อไร**

ตัวชี้ที่ไม่บอกเงื่อนไข เช่น "ดูเพิ่มที่ references/x.md" ทำให้ AI เปิดบ้างไม่เปิดบ้าง

## เขียนสิ่งที่ต้องทำ แทนการห้าม

- "ใช้ช่อง `รอยืนยัน` แทนข้อมูลที่ไม่มี" ดีกว่า "ห้ามแต่งข้อมูล" เพราะบอกทางที่ถูกให้ทำ
- ข้อห้ามที่ยังต้องมี (เช่น ห้ามอนุมัติแทนผู้มีอำนาจ) ให้คู่กับสิ่งที่ควรทำแทนเสมอ

## ตัดประโยคที่ไม่เปลี่ยนพฤติกรรม

- ประโยคที่โมเดลทำอยู่แล้วโดยไม่ต้องบอก เช่น "ตอบอย่างมืออาชีพ" เพิ่ม context โดยไม่ได้อะไร ให้ลบทั้งประโยค
- ความหมายเดียวอยู่ที่เดียว ถ้าข้อมูลอยู่ใน registry หรือเอกสารแล้ว ให้ชี้ไป อย่าคัดลอกมา เพราะสำเนาจะล้าสมัย
