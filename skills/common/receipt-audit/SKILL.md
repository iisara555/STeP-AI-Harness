# การตรวจสอบใบเสร็จรับเงินและวินิจฉัยข้ามบริบท (Receipt & Invoice Audit)

Skill นี้ใช้สำหรับตรวจสอบความถูกต้องครบถ้วนของใบเสร็จรับเงิน ใบกำกับภาษี (Tax Invoice) และชุดเอกสารเบิกจ่ายตามระเบียบมหาวิทยาลัยเชียงใหม่และหน่วยงานภาครัฐ เพื่อคัดกรองจุดเสี่ยง รายการที่ไม่ถูกต้องตามกฎหมาย และความไม่สอดคล้องกับงบประมาณที่ได้รับอนุมัติ

> [!IMPORTANT]
> **หลักการควบคุม (Human-in-the-Loop):**  
> ผลการตรวจของ Skill นี้เป็น **"รายงานข้อตรวจพบเบื้องต้น (Audit Finding)"** เพื่อช่วยเจ้าหน้าที่และผู้เบิกเตรียมเอกสารให้ถูกต้อง ไม่ถือเป็นคำสั่งจ่ายเงินหรือการอนุมัติการเบิกจ่ายทางการเงินขั้นสุดท้าย เจ้าหน้าที่การเงินและผู้มีอำนาจอนุมัติที่เป็นมนุษย์ต้องเป็นผู้ตรวจสอบและลงนามจริงเสมอ

---

## ข้อมูลบริบทที่ต้องนำมาใช้ร่วมกันในการวินิจฉัย (Cross-Context Inputs)

เพื่อให้การวินิจฉัยแม่นยำและตรวจพบความผิดปกติได้ครบถ้วน ให้ขอหรือรวบรวมข้อมูลอย่างน้อย 2 มิติขึ้นไป:

1. **เอกสารใบเสร็จ/ใบกำกับภาษี (Primary Document):** รูปถ่าย, ไฟล์ PDF หรือข้อความจากใบเสร็จรับเงิน หรือใบกำกับภาษีเต็มรูป
2. **เอกสารขออนุมัติหลัก (Approval Context):** บันทึกข้อความขออนุมัติโครงการ, ขออนุมัติจัดซื้อจัดจ้าง หรือขออนุมัติเดินทางไปปฏิบัติงาน
3. **เอกสารจัดซื้อและการส่งมอบ (Procurement Context):** ใบเสนอราคา (Quotation), ใบสั่งซื้อ/สั่งจ้าง (PO) หรือใบตรวจรับพัสดุ
4. **เกณฑ์และระเบียบเทียบเคียง:** อ้างอิงเกณฑ์ใน [receipt-rules-cmu.md](references/receipt-rules-cmu.md)

---

## ขั้นตอนการตรวจสอบและวินิจฉัย 4 มิติ

### มิติที่ 1: ตรวจสอบความสมบูรณ์ของใบกำกับภาษีตามกฎหมาย (Tax Invoice Compliance)

ตรวจ 9 รายการตามมาตรา 86/4 แห่งประมวลรัษฎากร:
- [ ] **1. ข้อความระบุประเภท:** มีคำว่า "ใบกำกับภาษี" หรือ "ใบเสร็จรับเงิน/ใบกำกับภาษี" เด่นชัด
- [ ] **2. ข้อมูลผู้ขาย (ผู้ออก):** ชื่อ ที่อยู่ เลขประจำตัวผู้เสียภาษี 13 หลัก และระบุสำนักงานใหญ่หรือสาขา
- [ ] **3. ข้อมูลผู้ซื้อ (มหาวิทยาลัย):**
  - ชื่อ: ต้องออกในนาม **"มหาวิทยาลัยเชียงใหม่"** หรือ **"มหาวิทยาลัยเชียงใหม่ (อุทยานวิทยาศาสตร์และเทคโนโลยี)"**
  - *ข้อผิดพลาดที่พบบ่อย:* ออกเป็นชื่อบุคคลธรรมดา (ชื่อผู้ประสานงาน/อาจารย์) หรือชื่อย่อที่ไม่ถูกต้อง -> **ต้องแจ้ง FLAG ทันที**
  - ที่อยู่: ที่อยู่สำนักงานใหญ่ มช. หรือที่อยู่อาคาร STeP
  - เลขประจำตัวผู้เสียภาษีอากร 13 หลักของ มช.: **`0994000164973`** และระบุสำนักงานใหญ่/สาขา
- [ ] **4. เลขที่และเล่มที่:** มีเลขที่ (และเล่มที่ ถ้ามี) ปรากฏชัดเจน
- [ ] **5. วัน เดือน ปี:** ระบุวันเดือนปีที่ออกเอกสารอย่างชัดเจน
- [ ] **6. รายการสินค้า/บริการ:** ระบุชื่อ ชนิด ปริมาณ และมูลค่าชัดเจน
- [ ] **7. การคำนวณภาษีมูลค่าเพิ่ม (VAT 7%):**
  - แยกแสดงมูลค่าก่อนภาษี (Net Amount), ภาษีมูลค่าเพิ่ม 7% (VAT), และยอดรวมสุทธิ (Total Amount)
  - ตรวจสอบความถูกต้องของคณิตศาสตร์: `ยอดก่อน VAT x 0.07 = ยอด VAT`
- [ ] **8. ยอดรวมตัวเลขและตัวอักษร:** ตัวเลขและตัวอักษรภาษาไทยต้องตรงกันทุกประการ
- [ ] **9. ความสมบูรณ์ของเอกสาร:** ไม่มีรอยลบ ขูด ขีด ฆ่า หากเป็น e-Tax Invoice ต้องมี Digital Signature ที่ถูกต้อง

### มิติที่ 2: การวินิจฉัยเชื่อมโยงข้ามบริบท (Cross-Context Diagnostics)

นำข้อมูลจากใบเสร็จไปเทียบเคียงกับบริบทแวดล้อม:

1. **เทียบกับบันทึกข้อความขออนุมัติโครงการ/งบประมาณ:**
   - **กรอบเวลา (Time Window):** วันที่ในใบเสร็จต้องอยู่ในช่วงเวลาที่ได้รับอนุมัติให้ดำเนินโครงการหรือเดินทางไปปฏิบัติงาน (ใบเสร็จที่ลงวันที่ก่อนวันอนุมัติหรือหลังสิ้นสุดโครงการต้องมีเหตุผลหรือข้อยกเว้นรองรับ)
   - **ความสอดคล้องของวัตถุประสงค์ (Purpose Alignment):** รายการของที่ซื้อหรือบริการที่จ้างต้องตรงกับกิจกรรมและแผนงานที่ระบุในบันทึกขออนุมัติ
   - **วงเงินที่ได้รับอนุมัติ (Budget Ceiling):** ยอดรวมในใบเสร็จต้องไม่เกินวงเงินที่ได้รับอนุมัติไว้ในบันทึกข้อความ
2. **เทียบกับใบสั่งซื้อ / ใบเสนอราคา (PO & Quotation):**
   - รายการสินค้า/บริการ ปริมาณ และราคาต่อหน่วย ต้องตรงกับใบเสนอราคาและใบสั่งซื้อที่ตกลงกันไว้
   - ชื่อนิติบุคคลผู้รับเงินต้องตรงกับผู้เสนอราคาที่ได้รับคัดเลือก
3. **เทียบกับสถานะทางภาษีของคู่ค้า (Vendor Tax Status):**
   - หากคู่ค้าคิด VAT 7% ต้องมีสถานะเป็นผู้จดทะเบียนภาษีมูลค่าเพิ่ม (ภ.พ.20)
   - หากคู่ค้าไม่ได้จด VAT จะออกได้เพียง "ใบเสร็จรับเงิน" เท่านั้น และห้ามแยกยอด VAT 7%
4. **เทียบกับเพดานระเบียบการเงินของมหาวิทยาลัย:**
   - ตรวจสอบค่าอาหารว่าง/เครื่องดื่ม (ไม่เกิน 35-50 บาท/มื้อ/คน ในสถานที่ราชการ)
   - ตรวจสอบค่าอาหารกลางวัน (ไม่เกิน 120-150 บาท/มื้อ/คน ในสถานที่ราชการ)
   - ตรวจสอบรายการต้องห้ามเบิกจ่าย: แอลกอฮอล์, ค่ามินิบาร์/ซักรีดส่วนตัว, รายการค่าใช้จ่ายส่วนตัว

---

### มิติที่ 3: ตรวจความครบถ้วนของชุดเอกสารประกอบการเบิกจ่าย (Disbursement Package)

จำแนกตามประเภทค่าใช้จ่าย:

| ประเภทค่าใช้จ่าย | เอกสารประกอบที่ต้องมีคู่กัน |
|---|---|
| **จัดซื้อวัสดุ / จ้างทำของ** | บันทึกขออนุมัติ + ใบเสนอราคา + ใบสั่งซื้อ (ถ้ามี) + ใบส่งของ/ใบกำกับภาษี + ใบตรวจรับพัสดุ + รูปถ่ายพัสดุ |
| **จัดประชุม / สัมมนา / อบรม** | บันทึกขออนุมัติโครงการ + กำหนดการ + ใบลงทะเบียนผู้เข้าร่วมประชุม + ใบเสร็จค่าอาหาร/เบรก + รูปถ่ายกิจกรรม |
| **เดินทางไปปฏิบัติงาน (ไปราชการ)** | บันทึกขออนุมัติเดินทาง + ตั๋วเครื่องบิน/ใบแจ้งหนี้ + กากบัตรขึ้นเครื่อง (Boarding Pass) + ใบเสร็จค่าที่พัก/Folio + ใบเสร็จค่าน้ำมัน (ระบุเลขทะเบียนรถ) |
| **จ้างวิทยากร** | หนังสือเชิญวิทยากร + กำหนดการ + ใบสำคัญรับเงินวิทยากร + สำเนาบัตรประชาชน (รับรองสำเนา) |

## รูปแบบผลการวินิจฉัย (Audit Finding Output Format)

ให้จัดทำรายงานผลการตรวจในรูปแบบตารางที่กระชับ ชัดเจน และอ่านเข้าใจง่ายทันที:

### 1. ข้อมูลสรุปเอกสาร (Document Header Summary)
- **เลขที่เอกสาร / วันที่:** ...
- **ผู้ออกเอกสาร (ผู้ขาย):** ... (ระบุเลขประจำตัวผู้เสียภาษี / สาขา)
- **ผู้ซื้อ:** ...
- **ยอดเงินสุทธิ:** ... บาท (รวม VAT ... บาท)
- **เอกสารบริบทที่นำมาใช้วินิจฉัยร่วม:** (เช่น บันทึกข้อความลงวันที่..., ใบเสนอราคาเลขที่...)

### 2. ตารางผลการตรวจสอบ (Audit Matrix)

| รายการตรวจ | สถานะ | ข้อตรวจพบ / ผลการวินิจฉัย | ข้อเสนอแนะ / สิ่งที่ต้องแก้ไข |
|---|:---:|---|---|
| ชื่อและเลขผู้เสียภาษีผู้ซื้อ | `PASS` / `FLAG` | ออกในนาม มช. ถูกต้อง หรือระบุจุดผิด | ... |
| ความถูกต้องตาม ม.86/4 | `PASS` / `FLAG` | แสดงยอดแยก VAT และรวมเงินถูกต้อง | ... |
| กรอบเวลาเทียบกับบันทึกอนุมัติ | `PASS` / `FLAG` | วันที่ใบเสร็จอยู่ในช่วงอนุมัติโครงการ | ... |
| รายการตรงกับ PO / ใบเสนอราคา | `PASS` / `FLAG` | ชนิด ปริมาณ ราคาต่อหน่วยตรงกัน | ... |
| เพดานค่าใช้จ่ายตามระเบียบ | `PASS` / `FLAG` | คำนวณต่อหัวไม่เกินเพดานที่กำหนด | ... |
| เอกสารแนบประกอบการเบิกจ่าย | `PASS` / `NEED_INFO` | มีใบตรวจรับและรูปถ่ายครบถ้วน | ... |

**คำอธิบายสถานะ:**
- `PASS (ผ่าน)`: ถูกต้องตามกฎหมาย ระเบียบ และสอดคล้องกับเอกสารบริบท
- `FLAG (ข้อบกพร่อง/จุดเสี่ยง)`: ผิดระเบียบ ไม่ตรงกับใบอนุมัติ หรือคำนวณภาษีผิดพลาด ต้องแก้ไขเอกสารก่อนเบิกจ่าย
- `NEED_INFO (ขอข้อมูลเพิ่ม)`: ขาดเอกสารแนบ หรือไม่มีข้อมูลเปรียบเทียบเพียงพอ

### 3. สรุปผลและการดำเนินการถัดไป (Next Actions for Officer)
- สรุปความพร้อมในการส่งเบิกจ่าย: `พร้อมส่งเบิกจ่าย` หรือ `ต้องแก้ไขเอกสารก่อนส่งการเงิน`
- รายการสิ่งที่ต้องขอจากผู้ขายหรือผู้เบิกเพิ่มเติม (เป็นข้อๆ ชัดเจน)

## Privacy Gate ก่อนตรวจเอกสาร

ก่อนส่งเนื้อหาเอกสารการเงินเข้า AI ให้ใช้กติกาใน `rules/data-classification.md`

หลักปฏิบัติ:
- ใช้ Quick Local Scan ก่อน
- ปิดบังเลขประจำตัวบุคคล เลขบัญชี เบอร์โทร ที่อยู่ส่วนตัว และข้อมูลที่ไม่จำเป็นต่อการตรวจ
- หากต้องตรวจว่า "ข้อมูลสองเอกสารตรงกันหรือไม่" ให้ใช้ token เดียวกัน เช่น `PERSON_001` แทนชื่อจริงเมื่อทำได้
- เลขประจำตัวขององค์กรที่เป็นข้อมูลสาธารณะและจำเป็นต่อการตรวจสามารถ allowlist ได้ โดยต้องมี source ที่ยืนยันว่าเป็นขององค์กร ไม่ใช่บุคคล
- หากพบข้อมูลอ่อนไหวร่วมกับตัวระบุบุคคล ให้หยุดการส่งไป AI ภายนอกและให้ผู้ใช้/เจ้าของกระบวนการยืนยัน
- ห้ามนำ Raw PII ไปใส่ใน Run Log, Feedback หรือ diagnostic output

ผลการตรวจควรแสดงเฉพาะข้อมูลที่จำเป็นต่อเหตุผล เช่น "ชื่อผู้รับเงินตรงกัน" แทนการพิมพ์ชื่อจริงซ้ำโดยไม่จำเป็น
