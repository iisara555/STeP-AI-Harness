# สัญญา snapshot สำหรับคำสั่ง preview

ผู้ดูแลจัดทำ snapshot ในพื้นที่จำกัดสิทธิ์จากแหล่งที่กำหนด ขนาดไฟล์สูงสุด 2 MiB โครงสร้างรับเฉพาะ metadata ด้านล่าง

```json
{
  "schema": 1,
  "sources": {
    "mis": {
      "status": "complete",
      "records": [
        {
          "id": "QP-DEMO-001",
          "revision": "02",
          "effectiveDate": "2026-11-23",
          "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
          "state": "active"
        }
      ]
    },
    "gmail": { "status": "complete", "records": [] },
    "sheets": { "status": "unavailable", "records": [] }
  }
}
```

- ทุก snapshot ระบุแหล่งทั้งสาม ใช้ `complete` เมื่ออ่านขอบเขตที่กำหนดครบ `partial` เมื่อข้อมูลบางส่วนยังตรวจไม่ได้ `unavailable` เมื่อแหล่งใช้งานไม่ได้ และ `not-configured` เมื่อยังไม่ได้ตั้งตัวอ่านแหล่งนั้น (ไม่มีรายการ และไม่ต้องตรวจเพิ่ม ยกเว้นรอบที่ตรวจแล้วเคยมีรายการจากแหล่งนั้น)
- `snapshot.mjs --mis` สร้างส่วน MIS ให้เอง รายการ Master List ใช้รหัส `ML-` ตามชื่อ เช่น `ML-AFP` REV ที่ MIS แสดงเป็น - ใช้ `none` และ `sha256` คือ digest ของแถวทะเบียน (เลขที่ ประเภท REV วันที่ ชื่อ สถานะ) เพราะ MIS ไม่มีเนื้อหาไฟล์ แถวที่อ่านไม่ได้หรือเลขเดียวกันมีสองแถวต่างกันจะถูกตัดออก และทำให้ MIS เป็น `partial`
- `id` คือรหัสที่ผู้ดูแลกำหนดให้เอกสารเข้าใจตรงกันข้ามแหล่ง ใช้ A–Z, 0–9 และขีด คำนวณ `sha256` จากเนื้อหาฉบับเดียวกันในรูปแบบคงที่ ข้อมูลย่อหรือเอกสารประกอบที่ไม่ใช่ฉบับเดียวกันควรใช้รหัสของตน และเชื่อมความสัมพันธ์ในทะเบียนภายใน
- ใช้ `withdrawn` เมื่อหลักฐานต้นทางระบุเพิกถอน ตรวจวัน ISO ตามเอกสารจริงและเก็บหลักฐานเมื่อแปลงปี พ.ศ. รายการที่วันมีผลหรือฉบับยังไม่ชัดให้ตรวจในพื้นที่จำกัดสิทธิ์ก่อนใส่ snapshot และรายงานแหล่งนั้นเป็นบางส่วน
- ไฟล์ก่อนหน้าเป็น snapshot ที่ผ่านการตรวจแล้ว รุ่นใหม่ที่เสนอมี `review-new` หรือ `review-change` การเพิกถอนเป็น `verify-withdrawal` รายการหายจากผลที่ครบเป็น `verify-missing` และไม่มีการอนุมานการลบจากผลบางส่วน
- เมื่อรายการเดียวกันจากสองแหล่งที่อ่านครบมีฉบับ วันมีผล สถานะ หรือ digest ต่างกัน ให้ตรวจ `disagreements` ผู้ดูแลตรวจอำนาจของแหล่งก่อนเลือกฉบับ เมื่อฝั่งใดอ่านไม่ครบ สถานะยังเห็นได้ใน `sourceStatus`
- เก็บ snapshot และรายงานนอก repository แม้โครงสร้างตัดเนื้อหาเอกสารออกแล้ว ส่วน auditor ในองค์กรตรวจย้อนหลังจากรหัสที่ผูกหลักฐานในพื้นที่จำกัดสิทธิ์
