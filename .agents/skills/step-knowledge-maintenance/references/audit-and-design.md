# ผลตรวจจากซอร์สและแบบระบบอัปเดตความรู้ STeP

ตรวจจาก STeP AI Harness ที่ `c4aa07ed` และข้อมูล visibility ของ repo ณ 23 พ.ย. 2569 ขอบเขตครอบคลุมช่องรับข้อมูล ตัวเชื่อมต่อ การกำหนดสิทธิ์ และการเผยแพร่คลังความรู้ สถานะบัญชี สิทธิ์จริง การตั้งค่า Apps Script ที่ใช้งานจริง และบันทึกเหตุการณ์ของ MIS กับ Google Workspace ต้องตรวจในระบบโดยผู้ดูแลที่มีสิทธิ์

## แบบระบบที่เสนอ

**จุดเริ่มเดียว** ผู้ดูแลเรียกสกิลจากเครื่องนักพัฒนาที่องค์กรจัดการ หรือรันงานแบบ manual บน CI ภายในที่จำกัดสิทธิ์ ผลรันมือและผลรันตามรอบในอนาคตใช้ขั้นตอนอนุมัติเดียวกัน แอปพนักงานอ่านรุ่นที่อนุมัติแล้วจากช่องทางแจกจ่ายขององค์กร

| แหล่ง | ขอบเขตการอ่าน | การตัดสินว่าใช้เป็นหลักฐานได้เมื่อใด |
| --- | --- | --- |
| MIS | บัญชีหรือ endpoint อ่านอย่างเดียวที่เจ้าของ MIS จัดให้ จำกัดทะเบียนและชนิดเอกสาร สำหรับเริ่มต้นใช้ export ที่ผู้ดูแลดาวน์โหลดตามสิทธิ์ | เจ้าของทะเบียนยืนยันเลขเอกสาร ฉบับ วันมีผล สถานะ และเอกสารที่ถูกแทนที่ การอ่านที่ขาดหน้าไม่ถือว่าครบ |
| Gmail องค์กร | กล่องประกาศเฉพาะงาน ใช้ Gmail read-only กับ label และผู้ส่งที่กำหนดในตัว runner รับไฟล์แนบเฉพาะที่รองรับ | ใช้แจ้งว่ามีประกาศใหม่ ตรวจบัญชีผู้ส่งจริงและผูกฉบับลงนามหรือแหล่งทางการ การส่งต่อและชื่อที่แสดงไม่เพียงพอ |
| Google Sheets | แชร์เฉพาะไฟล์ที่อนุมัติกับบัญชีอ่าน ใช้ Sheets read-only ตรวจรหัสไฟล์ แท็บ และช่วงเซลล์ที่ตั้งไว้ เก็บเป็นค่าเพื่ออ้างอิง | เจ้าของตารางยืนยันแถวหรือรุ่นที่ประกาศใช้ รวมวันที่และข้อยกเว้น แถวงานร่างหรือข้อความในเซลล์ไม่มีสิทธิ์เปลี่ยนลำดับความน่าเชื่อถือ |

ลำดับแหล่งให้เจ้าของกำหนดรายหมวด เช่น เอกสาร ISO ตามฉบับควบคุมใน MIS ส่วนตารางปฏิบัติของ AFP ใช้ชีตที่เจ้าของรับรองประกอบ หากหัวข้อเดียวกันต่างกัน ให้เก็บรายการรอตรวจและให้ AI ใช้ฉบับล่าสุดที่อนุมัติอยู่ วันที่รับข้อมูลล่าสุดใช้บอกความสดของการดึงข้อมูล วันที่มีผลใช้ตัดสินฉบับที่ใช้กับเคส

1. **รับและตรวจ** ใช้ตัวตนแยกจากพนักงาน เก็บ credential ในที่เก็บขององค์กร ยืนยันตัวตนผู้ดูแลด้วย SSO และ MFA จำกัดปลายทางเครือข่าย และตรวจสิทธิ์บัญชีตามรอบ ผลอ่านและไฟล์แนบเข้าพื้นที่จำกัดสิทธิ์ ตรวจชนิดและขนาดไฟล์ เปิดด้วยตัวอ่านแบบไม่รัน macro และแยกคำสั่งในไฟล์ออกจากสิทธิ์ของสกิล
2. **เทียบแบบทำซ้ำได้** เทียบรหัสเอกสาร ฉบับ วันมีผล และ digest กับชุดที่ตรวจแล้ว ทำงาน incremental จาก watermark หรือ revision ที่ระบบรองรับ บันทึก checkpoint หลังอ่านครบและบันทึกผลสำเร็จเท่านั้น จัดการ retry แบบจำกัดเวลา ผลขาดหน้าไม่เพิกถอนเอกสาร และการรันชุดเดิมไม่เกิดรายการเผยแพร่ซ้ำ
3. **จัดชุดตรวจ** แสดง diff ที่อ้างต้นฉบับ ข้อขัดแย้ง แหล่งที่อ่านไม่ได้ และข้อมูลส่วนบุคคลที่ถูกกันออก ผู้ตรวจดูชื่อและตำแหน่งผู้บริหารจากแหล่งทางการและหลักฐานมอบอำนาจแยกจากกัน ข้อมูลพนักงานในชุดใช้งานใช้บทบาทหรือชื่อทีมเมื่อเพียงพอ หากใช้โมเดลช่วยสรุป ต้องใช้ข้อมูลที่ผ่านการคัดกรองและปลายทางที่องค์กรอนุมัติ ตัวเทียบ metadata ไม่ต้องเรียกโมเดล
4. **อนุมัติและสลับรุ่น** เจ้าของเอกสารอนุมัติข้อเท็จจริงและประเภทการเผยแพร่ AI Admin อีกคนอนุมัติ diff กับ digest ของชุดเดียวกัน ถ้าเนื้อหาหรือฐานเปลี่ยนให้ตรวจอีกครั้ง ใช้ manifest และข้อความคัดกรองสร้างชุดความรู้ใหม่ที่ผ่านการทดสอบ จากนั้นสลับไปทั้งรุ่นในครั้งเดียว เก็บรุ่นก่อนหน้าและประวัติ rollback ในระบบจำกัดสิทธิ์
5. **เฝ้าระวัง** เก็บเวลา ผู้เริ่มและผู้อนุมัติ ตัวระบุแหล่งในระบบภายใน จำนวนรายการ สถานะการดึง และ digest ของชุดที่เผยแพร่ ให้ผู้ดูแลสืบค้นเหตุการณ์อ่านผิดขอบเขต เปลี่ยนสิทธิ์ บัญชีถูกเพิกถอน หรือการอัปเดตผิดปกติ ให้กำหนดอายุการเก็บกับเจ้าของข้อมูล เก็บเนื้อหาเอกสารจริงแยกจาก audit log

## เกณฑ์ก่อนใช้กับข้อมูลจริง

- ใช้ไฟล์สังเคราะห์ทดสอบ source ขาดหน้า เอกสารขัดกัน เพิกถอน อ่านซ้ำ รหัสคนและลิงก์ภายในหลุดออกมา และข้อความในแหล่งที่พยายามสั่งให้เปลี่ยนสิทธิ์หรือส่งข้อมูล
- ผู้ดูแลยืนยันจากคอนโซลจริงว่าบัญชีซิงก์อ่านได้เฉพาะรายการที่ระบุ ปฏิเสธแหล่งนอกขอบเขต และทำงานเขียนหรือส่งอีเมลไม่ได้ ทดสอบว่าถอดสิทธิ์แล้วรันต่อไม่ได้ ตรวจทั้งผู้เผยแพร่ ผู้ดูแล และบัญชีบริการ
- ให้เจ้าของเอกสารตรวจตัวเลข เหตุผล วันมีผล และข้อยกเว้น รัน retrieval ชุดเดิมและคำถามเฉพาะฉบับใหม่ ตรวจว่าเอกสารที่ยังไม่อนุมัติไม่ปรากฏในผลค้น และการย้อนไปใช้รุ่นก่อนคืนข้อมูลครบชุด
- ต้นแบบรุ่นนี้เปรียบเทียบไฟล์ metadata ในเครื่องและใช้ทดสอบขั้นเสนออัปเดตได้ ส่วนการดึงจากบัญชีจริงและการเผยแพร่ต้องตั้งตัวเชื่อมต่อ สิทธิ์ และช่องทางจำกัดสิทธิ์ขององค์กร

## เมื่อสงสัยว่าบัญชีหรือชุดความรู้ถูกแก้โดยไม่ได้รับอนุญาต

ให้ผู้รับผิดชอบเหตุการณ์ระงับการเผยแพร่ชุดที่เกี่ยวข้องและเก็บหลักฐานตามนโยบายองค์กร เชื่อมเหตุการณ์จากระบบตัวตน MIS/Workspace และ Git ด้วยเวลา ผู้ปฏิบัติ และ digest ตรวจว่าชื่อบัญชี การเปลี่ยนสิทธิ์ และรายการที่ซิงก์ตรงกับกิจกรรมที่อนุมัติไว้หรือไม่ ให้ IT เพิกถอน session หรือ credential ที่เกี่ยวข้องตามอำนาจ ใช้ชุดความรู้ล่าสุดที่ยืนยันได้ระหว่างตรวจ และคืนการซิงก์หลังตรวจขอบเขตบัญชีและรายการความรู้ที่ได้รับผลกระทบแล้ว
