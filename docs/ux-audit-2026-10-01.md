## วิธีทดลองและขอบเขต

- เปิด Electron build ในโปรไฟล์ใหม่แยกจากบัญชีส่วนตัว ตั้ง `STEP_CLAUDE_SUBSCRIPTION=0`; ผลของ deployment ที่เปิดสิทธิ์อื่นอาจต่างกัน
- เดินผ่านหน้าต้อนรับ โปรไฟล์ บุคลิกผู้ช่วย เชื่อม AI โฟลเดอร์/ส่วนเสริม หน้าจบ หน้างานว่าง ตั้งค่า AI ขั้นสูง Claude Console และหน้าจอเล็ก รวม 11 จุดบันทึก
- ใช้ขนาด 1280×800 แล้ว 800×650: ไม่พบ renderer page error หรือ horizontal overflow ในจุดที่ตรวจ ไม่ใช่การรับรอง accessibility ทั้งระบบ
- รัน `account-connect-smoke.mjs`: ผ่านการแสดงหน้าบัญชีอย่างง่าย สั่งเริ่มเชื่อมอัตโนมัติ และล้างค่าขั้นสูงเมื่อย้อนกลับ ใช้ IPC จำลอง ไม่ได้ล็อกอินจริง
- รัน `tool-loop-smoke.mjs`: ผ่าน consent, คำถามถึงผู้ใช้, อนุมัติแผน, staged changes, usage และ cancellation โดยใช้ provider จำลอง
- รัน `browser-agent-smoke.mjs`: ผ่านหน้าเว็บจริงในเครื่อง ทั้ง read/fill/click, ปฏิเสธ, ref หมดอายุ, เป้าหมายเปลี่ยนระหว่างรออนุญาต, แยกเจ้าของงาน, ซ่อนหน้า login และปฏิเสธ URL ที่ไม่รองรับ
- ทดสอบตัวเลือกวิธีทำงานด้วยคำขอสังเคราะห์ 4 กรณี ไม่เรียก AI ภายนอก ไม่ส่งข้อมูลพนักงาน
- ยังไม่ได้ทดลอง OAuth กับบัญชีจริง, token หมดอายุ, คุณภาพคำตอบ AI, export เอกสารทุกชนิด, installer เครื่องใหม่, screen reader, เว็บองค์กร หรือพนักงานจริง จึงไม่อ้างว่าผ่านหัวข้อเหล่านี้

## ข้อค้นพบและวิธีแก้

### P1 · F01 แจ้งพร้อมทั้งที่ยังเริ่มงาน AI ไม่ได้

**พบจริง:** ข้ามขั้นเชื่อม AI แล้วหน้าสุดท้ายขึ้น “พร้อมเริ่มงานแล้ว” พร้อมเครื่องหมายขั้นที่ผ่านมา ข้อความว่ายังไม่เชื่อม AI มีขนาดเล็กกว่า เมื่อเข้าหน้างานจึงเห็นว่าต้องเชื่อมต่อก่อน แหล่ง: `desktop/src/setup.tsx:357` และภาพ `06-ready-without-ai.png`

**แก้:** แยก “บันทึกการตั้งค่าแล้ว” กับ “พร้อมเริ่มงาน” ตามสถานะบัญชี แสดงขั้นที่ข้ามเป็น “ทำภายหลัง” และให้ปุ่มหลักเป็น “เชื่อมต่อ AI” เมื่อยังไม่มีบัญชีพร้อมใช้ ให้เข้าชมพื้นที่ทำงานต่อได้ด้วยปุ่มรอง

**เกณฑ์ผ่าน:** โปรไฟล์ใหม่ที่ข้าม AI ไม่เห็นคำว่าพร้อมใช้งาน AI; กลับไปเชื่อมได้จากหน้าจบในคลิกเดียว; บัญชีที่พร้อมแล้วจึงเสนอเริ่มงาน

### P1 · F02 บัญชีที่พนักงานต้องการยังไม่ครบเส้นทางใช้งาน

**พบจริง:** หน้าอย่างง่ายมี ChatGPT ใช้งานได้ แต่ Claude และ Gemini ถูกปิดพร้อมคำอธิบาย ในหน้างานยังมีตัวเลือกเปิด Claude Code ภายนอก จึงมีหลายความหมายของคำว่า “เชื่อม Claude” แหล่ง: `desktop/src/ui.tsx:487` และภาพ `04-ai-connect.png`, `07-empty-workspace.png`

**แก้:** ระบุบัญชีที่องค์กรรองรับจริงเป็นตัวเลือกหลัก แยก “ใช้งานใน STeP” กับ “เปิดแอปภายนอก” ให้ชัด จัดเส้นทางที่ผู้ดูแลเตรียมให้พนักงานก่อนเปิดใช้งานวงกว้าง ไม่เพียงปลด disabled หรือใช้วิธีเชื่อมที่ยังไม่พร้อม

**เกณฑ์ผ่าน:** ทุกบัญชีที่ประกาศรองรับต้องผ่านเครื่อง/โปรไฟล์ใหม่ → เข้าสู่ระบบ → ได้คำตอบแรก → เปิดแอปใหม่ → สิทธิ์หมดอายุแล้วเชื่อมใหม่ พร้อมคำแนะนำภาษาไทย โดยทดสอบกับบัญชีจริงที่ได้รับอนุญาต ปัจจุบันยังไม่มีหลักฐานนี้จาก audit รอบนี้

### P1 · F03 คำขอชัดเจนยังถูกถามกลับผิดประเภท

| คำขอทดสอบ | ผลจริง | ประเมิน |
|---|---|---|
| ช่วยสรุปบันทึกประชุมเป็นรายการงาน (`--team qs`) | `SKILL: meeting-summary` | ตรงเจตนา |
| ช่วยเตรียม checklist ตรวจติดตามคุณภาพภายใน ISO 9001 (`--team qs`) | ถามว่าต้องการตรวจ/สรุป/จัดทำอะไร | ไม่ใช้ข้อมูลที่คำขอบอกแล้ว ควรถามขอบเขตการตรวจถ้าจำเป็น |
| ช่วยร่างอีเมลเชิญประชุมทีม (`--team qs`) | เสนอ meeting-summary, stakeholder-questionnaire, sop-authoring | ตัวเลือกไม่ตรงการร่างคำเชิญ |
| ขอใช้แนวคิดจาก URL browser-harness พัฒนาตัวเชื่อมเว็บ พร้อมคำตอบ “พัฒนาตัวเชื่อมเบราว์เซอร์ใน STeP” | ยัง `CLARIFY` เสนอ GitHub Issues/Projects/Labels/Automation | URL มีผลเหนือคำชี้แจงเจตนา |

**แก้:** ให้น้ำหนักสิ่งที่ผู้ใช้ต้องการทำและคำตอบล่าสุดเหนือชื่อเว็บไซต์ ใช้ GENERAL สำหรับงานทั่วไปที่ไม่มีขั้นตอนเฉพาะและผ่านข้อกำกับ แยกความไม่ชัดของประเภทงานออกจากข้อมูลเนื้อหาที่ยังขาด หากคำชี้แจงไม่ทำให้ผลเปลี่ยน ให้ถามเจาะจงใหม่แทนคำถามเดิม โดยคงข้อกำกับสิทธิ์และข้อมูลไว้

**เกณฑ์ผ่าน:** เพิ่ม regression ของทั้ง 4 คำขอ รวมกรณีมี/ไม่มี URL; คำเชิญประชุมต้องขอวัน เวลา ผู้เข้าร่วมเมื่อขาด ไม่บังคับเลือก SOP; คำขอพัฒนาตัวเชื่อมต้องไม่เสนอการจัด GitHub Project ซ้ำ

### P2 · F04 งานสั้นต้องอนุญาตหลายครั้ง

**พบจริง:** ใน `desktop/test/tool-loop-smoke.mjs` เส้นทางอ่าน note → ถามรูปแบบ → วางแผน → เตรียมร่าง มี consent ส่งผลให้ AI 4 ครั้ง และอนุมัติแผนอีก 1 ครั้ง รวม 5 ครั้ง ไม่รวมการตอบคำถาม รูปแบบนี้เป็นเส้นทางจำลอง ไม่ใช่จำนวนเฉลี่ยของทุกงาน และยังไม่ได้วัดความเหนื่อยของพนักงาน

**แก้:** ประเมินรวมการอนุญาตอ่าน/ส่งข้อมูลความเสี่ยงต่ำภายในขอบเขตงานที่แจ้งชัด โดยระบุไฟล์ ผู้รับข้อมูล อายุสิทธิ์ และการถอนสิทธิ์ ไม่รวมสิทธิ์ส่งข้อความจริง กดส่งแบบฟอร์ม จ่ายเงิน หรือเปลี่ยนเป้าหมายไว้ในสิทธิ์เหมารวม

**เกณฑ์ผ่าน:** เส้นทางสรุป note ไม่ถามซ้ำสำหรับขอบเขตที่อนุญาตแล้ว; เปลี่ยนผู้รับ/ไฟล์/ระดับข้อมูลต้องถามใหม่; ปฏิเสธแล้วไม่ส่งข้อมูล; ทุกการกระทำที่มีผลจริงยังผ่านคนอนุมัติ

### P2 · F05 วิธีคิดค่าใช้จ่ายและการเชื่อมมีหลายแบบ

**พบจริง:** ขั้นสูงมี “Claude Console OAuth (ไม่ต้องใช้ API key)” พร้อมข้อความอธิบาย API quota ที่ถูกต้อง แต่พนักงานยังต้องแยกจาก Claude Pro/Max และการเปิด Claude Code ภายนอก แหล่ง: `desktop/src/ui.tsx:430`, `:591`, `:603` และภาพ `10-claude-console.png` ไม่ได้พบการเรียกเก็บเงินผิดในการทดสอบนี้

**แก้:** ทุกตัวเลือกแสดง “ใช้แพ็กเกจส่วนตัว / ใช้งบ API องค์กร / เปิดแอปอื่น” ใกล้ปุ่มเริ่ม แสดงเจ้าของบัญชีและผู้รับผิดชอบค่าใช้จ่ายก่อนยืนยัน ไม่เปลี่ยนไปใช้ API ที่เสียค่าใช้จ่ายโดยเงียบ

**เกณฑ์ผ่าน:** ผู้ทดลองอธิบายได้ว่าตัวเลือกที่ตนเลือกใช้สิทธิ์ใครและคิดค่าใช้จ่ายแบบใด โดยไม่ต้องเปิดคู่มือ

### P2 · F06 การตั้งค่าและคำศัพท์มาก่อนผลงานแรก

**พบจริง:** wizard มี 6 ขั้น รวมโฟลเดอร์, `USER.md`, CLI และตัวเลือก OCR ประมาณ 1–2 GB; หน้างานมี Chat, Draft / Output, Image, Browser, Terminal, Tasks, Files, Changes แหล่ง: `desktop/src/setup.tsx:210`, `:314`, `desktop/src/App.tsx:1340` OCR เป็นตัวเลือก ไม่ได้บังคับดาวน์โหลด

**แก้:** ให้เริ่มจากบัญชีและงานตัวอย่างภาษาไทย เลื่อนบุคลิก/โฟลเดอร์/ส่วนเสริมไปเมื่อจำเป็น แสดง OCR เมื่อมีงานเอกสารสแกน ใช้ชื่อ “คุยกับผู้ช่วย”, “สร้างเอกสาร”, “เว็บ”, “ไฟล์งาน”; เก็บ terminal/ค่าทางเทคนิคไว้ในส่วนขั้นสูง

**เกณฑ์ผ่าน:** พนักงานเริ่มงานตัวอย่างได้โดยไม่ต้องเข้าใจ USER.md, CLI หรือเลือก OCR; มีงานตัวอย่างเหมาะกับทีมที่เลือก

### P2 · F07 เว็บทำงานพื้นฐานได้ แต่ยังไม่พิสูจน์งานองค์กรครบวงจร

**พบจริง:** browser connector ผ่านการทดสอบเว็บในเครื่องและแยกโปรไฟล์จากส่วนตัว การทำงานข้าม origin ต้องเปิดใหม่หลังอนุญาต ไม่มี upload/download/iframe และต้องล็อกอินด้วยตนเอง ดู `docs/desktop-browser-agent.md` กับ `desktop/electron/tool-loop.ts:6`

**แก้:** เพิ่มทางเข้าภาษาไทย “ให้ผู้ช่วยทำงานบนเว็บ” พร้อมสถานะเว็บไซต์ ขั้นตอนถัดไป และหยุดงาน อธิบายข้อจำกัดเมื่อเกี่ยวข้องกับงานนั้น ทดสอบ SSO และงานอ่านข้อมูลบนเว็บองค์กรที่ได้รับอนุญาตก่อนประกาศรองรับ ไม่ถือว่าการคลิกสำเร็จเท่ากับส่งงานสำเร็จ

**เกณฑ์ผ่าน:** จากคำขอในหน้าคุย สามารถเปิดเว็บทดสอบ กรอก อ่านยืนยัน และรายงานผลผ่าน Agent ได้ครบ; ปฏิเสธแล้วไม่มีการกระทำ; งานที่ต้องใช้ upload/SSO ที่ยังไม่รองรับมีทางให้คนทำต่ออย่างชัดเจน การทดสอบ connector แยกส่วนที่ผ่านแล้วไม่ทดแทนเกณฑ์นี้

### P3 · F08 ปุ่มเชื่อมบัญชีพ้นขอบล่างบนหน้าต่างเล็ก

**พบจริง:** ที่ 800×650 ส่วนเลือกบัญชีปรากฏแต่ปุ่มเชื่อมอยู่ใต้บริเวณที่เห็น ต้องเลื่อน ภาพ `11-small-window.png`; ไม่พบการล้นแนวนอน ไม่ได้สรุปว่าปุ่มเข้าถึงไม่ได้ด้วย keyboard

**แก้:** วาง action หลักใน footer ที่เห็นได้เสมอเมื่อขนาดจำกัด ลดความสูงข้อความรอง และตรวจ focus เมื่อมี modal

**เกณฑ์ผ่าน:** ที่ขนาดหน้าต่างต่ำสุดที่รองรับ ปุ่มหลักมองเห็นได้หรือมีสัญญาณให้เลื่อนชัด; Tab เข้าถึงปุ่มได้ และ focus ไม่ออกหลัง modal

## ลำดับแก้ที่เสนอ

1. **ก่อนขยายกลุ่มทดลอง:** F01 สถานะพร้อม, F03 การเข้าใจคำขอ, F02 เส้นทางบัญชีที่รองรับจริง
2. **ลดภาระพนักงาน:** F04 การถามซ้ำ, F05 สิทธิ์/ค่าใช้จ่าย, F06 ขั้นตอนก่อนเริ่มงาน
3. **ก่อนประกาศเว็บเป็นความสามารถพร้อมใช้:** F07 ทดสอบงานจริงครบวงจร; เก็บ F08 ในรอบปรับหน้าจอ

ข้อเสนอสำหรับรอบตรวจถัดไป: พนักงานที่ไม่เคยใช้ 5 คน ทดลองเข้าสู่ระบบ สรุปประชุม สร้างร่างคำเชิญ และอ่านเว็บทดสอบ จดจำนวนคนที่ทำสำเร็จโดยไม่ช่วย เวลาไปถึงผลงานแรก จำนวนครั้งที่ต้องขอความช่วยเหลือ และความเข้าใจการอนุญาต แนะนำเกณฑ์รับงานอย่างน้อย 4/5 คนสำเร็จด้วยตนเอง ไม่มีการส่งข้อมูลหรือกระทำเกินอนุญาต เกณฑ์นี้เป็นข้อเสนอ ไม่ใช่ผลที่วัดได้แล้ว
