## ก่อนเริ่ม — STeP AI Geek เตรียม 15 นาที

1. ตรวจ SHA-256 ของ ZIP กับ sidecar ให้ตรงกันก่อนแจก แล้วแจกสองไฟล์จากช่องทางภายในเดียวกัน ไม่ใช้ ZIP v0.7.2 ที่เคย build จาก development source
2. แจ้งช่องทางติดต่อ STeP AI Geek ให้ผู้ทดสอบทุกคนทราบ และยืนยันว่าโปรแกรม AI/บัญชีและข้อมูลที่ใช้ได้รับอนุญาต
3. ลองติดตั้งและทำงานแรกบน Windows 1 เครื่องและ macOS 1 เครื่องด้วยโปรแกรมจริง อย่างน้อยหนึ่งเครื่องต่อโปรแกรม AI ที่จะใช้ ต้องเปิดโฟลเดอร์ชุดทดสอบเป็น workspace ได้
4. หากบาง OS/โปรแกรมยังไม่ผ่าน ให้พักเฉพาะกลุ่มนั้นและบันทึกปัญหา อย่านับว่าเตรียมพร้อมเพียงเพราะสร้าง instruction files ได้
5. ให้แต่ละคนใช้สำเนางานหรือข้อมูลสังเคราะห์ และสำรองโฟลเดอร์งานเดิมก่อนเริ่ม
6. ก่อนแนบเอกสาร เปิด `Check-Privacy-STeP-AI.bat` / `Check-Privacy-STeP-AI.command` ตรวจบนเครื่อง ให้คนตรวจเนื้อหาและสิทธิ์ต่อ; PDF/DOCX ต้องตรวจด้วยคนเสมอ รูปภาพ/ไฟล์สแกน/XLSX ยังตรวจไม่ได้ ห้ามอ้างว่า gate ดักการแนบให้ AI ได้ ดู [privacy-preflight.md](privacy-preflight.md)

ผู้ใช้ไม่ต้องเปิด Terminal: แตก ZIP แล้วเปิด `Install-STeP-AI.bat` หรือ `Install-STeP-AI.command` เลือกทีมของตนหรือข้ามได้ จากนั้นเปิดโฟลเดอร์ด้วยโปรแกรม AI ที่องค์กรอนุมัติ พิมพ์ `เริ่มใช้งาน STeP AI`

บน macOS ถ้าเปิดไฟล์ไม่ได้ ให้ทำตาม `MAC-START-HERE.txt` และแจ้ง STeP AI Geek; ไม่ปิดระบบความปลอดภัยของเครื่องทั้งระบบ บางเครื่องต้องใช้อินเทอร์เน็ตเพื่อเตรียม Node.js runtime และโปรแกรม AI

## เกณฑ์ตัดสินหลังรอบแรก

- ผู้ทดสอบอย่างน้อย 90% ติดตั้ง/เริ่มงานได้ โดยไม่ให้พนักงานแก้ระบบเอง
- งานหลัก 2 งานต่อคน: อย่างน้อย 80% ของงานที่ทดสอบใช้ต่อได้หลังแก้เล็กน้อย
- ไม่มีข้อมูลลับรั่ว ไม่มีการอนุมัติ/ส่ง/จ่ายจริงโดยไม่มีการยืนยัน และไม่มี user memory/output สูญหาย
- ปัญหาที่ทำให้คนใช้ต่อไม่ได้ต้องมีผู้รับผิดชอบและแนวทางแก้ก่อนขยายกลุ่ม
- บันทึกผล AI จริงแยกจากผล unit tests และ benchmark; benchmark ไม่วัดคุณภาพคำตอบหรือประสบการณ์พนักงาน

ถ้าพบข้อมูลลับรั่ว การกระทำจริงที่ไม่ได้รับอนุญาต ข้อมูลหาย หรือ checksum ไม่ตรง ให้หยุดเคสนั้น เก็บหลักฐานที่ปิดข้อมูลลับแล้ว และแจ้ง STeP AI Geek ทันที

## อัปเกรดและกู้คืน — สำหรับ STeP AI Geek

Pilot วันแรกใช้ fresh install เป็นหลัก เพื่อให้ทุกคนเริ่มจากชุดเดียวกัน ไม่แตก ZIP ทับ workspace เดิม การอัปเกรดผ่าน GitHub ต้องเข้าถึง release ได้และมี checksum; ถ้าเข้าถึงไม่ได้ การซิงก์ในเครื่องไม่ได้แปลว่าได้รับรุ่นใหม่แล้ว

เมื่อต้องซ้อมอัปเกรด ให้ทำบนสำเนา workspace ก่อน จากโฟลเดอร์ชุดใหม่ใช้ Node ที่มีอยู่หรือ runtime ของตัวติดตั้ง:

```text
node bin/step-ai.js upgrade-apply --dest <โฟลเดอร์เก่าที่สำรองแล้ว> --version <รุ่นของชุดใหม่ เช่น 0.7.4>
node bin/step-ai.js rollback --dest <โฟลเดอร์ทดสอบ> --list
node bin/step-ai.js rollback --dest <โฟลเดอร์ทดสอบ> --snapshot <pre-version-upgrade snapshot ID>
```

รัน rollback จากชุดรุ่นใหม่ที่แยกไว้ เลือก snapshot ก่อนอัปเกรดของเวอร์ชันที่ติดตั้งอยู่ และย้อนตามลำดับล่าสุดก่อน ระบบต้องคืน package/runtime/manifest พร้อมกัน พร้อมรักษา `USER.md`, `MEMORY.md`, `.env` และ `output/` ส่วนการแก้ไฟล์ระบบหลัง snapshot จะย้อนตาม snapshot นั้น

snapshot เก่าที่ไม่มีลิงก์ไป full distribution backup ไม่ควรถูกใช้เพื่อย้อน runtime คนละเวอร์ชัน; ใช้สำเนา workspace เต็มแทน

## อัปเดตผู้ทดสอบระหว่าง Pilot — v0.7.3 → v0.7.4

ผู้ทดสอบรอบแรกมี `USER.md`, `MEMORY.md` และ `output/` ของตัวเองแล้ว จึงใช้ตัวอัปเดต ไม่ให้แตก ZIP ใหม่ทับโฟลเดอร์เดิม

1. รอให้ GitHub Release v0.7.4 เผยแพร่และ CI เขียว แล้วตรวจ SHA-256 ของ ZIP กับ sidecar ให้ตรงกัน
2. ซ้อมบนสำเนา workspace v0.7.3 อย่างน้อย Windows 1 เครื่องและ macOS 1 เครื่อง ด้วยคำสั่ง `upgrade-apply` ด้านบน แล้ว rollback กลับหนึ่งครั้ง ต้องได้ `USER.md`, `MEMORY.md`, `.env` และ `output/` ครบทั้งสองทาง
3. หลังซ้อมผ่าน แจ้งผู้ทดสอบให้เปิด `Update-STeP-AI.bat` / `Update-STeP-AI.command` ตัวอัปเดตดึงรุ่นล่าสุดจาก GitHub Release และตรวจ checksum ก่อนติดตั้ง
4. ให้ผู้ทดสอบลองคำถามที่เพิ่มในรุ่นนี้หนึ่งข้อ เช่น "ลาพักผ่อนได้ปีละกี่วัน" หรือ "ขอออกใบเสร็จรับเงินใช้เวลากี่วันทำการ" แล้วบันทึกว่าได้คำตอบพร้อมอ้างอิงหรือไม่
5. บันทึกรุ่นที่ติดตั้งจริงของแต่ละคนในแบบบันทึกผู้ทดสอบ ถ้าอัปเดตไม่สำเร็จให้คงรุ่น v0.7.3 ไว้ แจ้ง STeP AI Geek และอย่าให้พนักงานแก้ระบบเอง

ถ้า checksum ไม่ตรง หรือไฟล์ส่วนตัวหายระหว่างการซ้อม ให้หยุดการอัปเดตทั้งกลุ่มตามเกณฑ์ STOP ใน [Pilot Readiness Audit](pilot-readiness-audit.md)

**สถานะเผยแพร่:** v0.7.3 เผยแพร่เป็น GitHub Release แล้วเมื่อ 21 กันยายน 2569 ส่วน v0.7.4 ยังเป็นรุ่นเตรียมออกจนกว่าจะมี GitHub Release และผ่าน Release Gate
