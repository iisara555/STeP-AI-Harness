# File and web assistant

This source-only workflow is selected as **ผู้ช่วยทำงานกับไฟล์และเว็บ** in the chat composer. The employee describes the task and can attach a document or use files in the selected workspace. It uses the existing governed tool loop and STeP Skill/organization-knowledge routing. A model still decides which available tool to request, so a connected model and real-account acceptance are separate from the host's synthetic tests.

The work-step list shows each host-confirmed tool attempt, including failures, using generic labels rather than paths or source contents. It records tool names, result status and diagnostic codes with the existing local run trace. A successful tool step is not a claim that the business task was approved, that a staged file was applied, or that a source was complete. Actual proposed files remain in Changes and are applied or staged according to the selected permission mode; existing snapshot and conflict controls remain in force.

The workflow requires both `features.toolLoop` and `checks.privacy` to be enabled in the trusted [managed policy](desktop-policy.md). `checks.privacy` is off in the app's default policy, so an administrator must enable it before this workflow starts. The host checks that requirement on send, before provider calls, and during tool work; changing policy interrupts further work. The privacy gate helps detect and mask data but does not establish that every sensitive item was found. Employees still review the source and data destination.

This initial scope reads pages in the app browser and reads permitted Google resources after the existing account and transmission consents. It does not click or fill web pages, use browser Vault, execute terminal/sandbox commands, call remote MCP tools or write to Google. A locally staged document remains editable and reviewable. These restrictions are enforced by the host, not only by instructions to the model. Other workflows keep their existing policy and permission behavior.

`test/work-assistant-smoke.mjs` runs the actual Electron interface and host with synthetic files, a local website and a synthetic model runtime. It checks policy denial, privacy masking, document and browser reads, a staged file, blocked command/Google write, step history after restart, and narrow/dark/English layouts. It does not use a real provider, Google account or employee data.
