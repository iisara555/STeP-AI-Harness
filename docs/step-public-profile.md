# STeP Public Profile — ข้อมูลทั่วไปจากแหล่งสาธารณะ

**ตรวจแหล่งครั้งล่าสุด:** 2026-09-20
**Provenance:** ทุกข้อในเอกสารนี้เป็น `SOURCE_FACT` จากเว็บไซต์ทางการสาธารณะ ไม่ใช่ `ORGANIZATION_RULE`
**ข้อจำกัด:** ข้อมูลสาธารณะไม่ใช่สิทธิ์อนุมัติและไม่แทนการยืนยันจากเจ้าของกระบวนการ (`manifest/services.yaml` → `publicDiscoveryIsNotAuthority: true`)

ค่าที่เครื่องอ่านได้อยู่ที่ [`manifest/organization.yaml`](../manifest/organization.yaml) → `publicProfile`
รายการแหล่งพร้อมสถานะ URL อยู่ที่ [`manifest/services.yaml`](../manifest/services.yaml) → `sources`

## 2. พันธกิจ 5 เสา

Research Utilization · Solution Provider · Incubator · Open Innovation · Infrastructure

หัวข้อชุดนี้สรุปจากหน้า aboutus สาธารณะ **ถ้อยคำทางการฉบับเต็มและปีเป้าหมายของวิสัยทัศน์ต้องยืนยันกับทีมยุทธศาสตร์ก่อนนำไปใช้ในเอกสารราชการ** เอกสารนี้จึงไม่คัดข้อความวิสัยทัศน์มาเต็มรูป

## 5. ดัชนีเอกสารเปิดเผยสาธารณะ (OIT/ITA 2569)

หน้า OIT เป็น **ดัชนีว่าเอกสารทางการอยู่ที่ใด** ไม่ใช่สำเนาเนื้อหา เมื่อ AI ต้องอ้างเนื้อหาต้องเปิดจากแหล่งจริงทุกครั้ง

| กลุ่ม | รายการ |
| --- | --- |
| โครงสร้างและอำนาจ | O1 โครงสร้าง หน้าที่และอำนาจ · O2 ข้อมูลผู้บริหาร |
| ติดต่อ/ประชาสัมพันธ์ | O3 ข้อมูลการติดต่อและช่องทางการสอบถาม · O4 ข่าวประชาสัมพันธ์ |
| แผนและผลดำเนินงาน | O5 แผนยุทธศาสตร์หรือแผนพัฒนาส่วนงาน · O6 แผนและความก้าวหน้าการใช้งบประมาณ 2569 · O7 รายงานผลการดำเนินงาน 2568 |
| คู่มือปฏิบัติงาน | O8 คู่มือการปฏิบัติงานของเจ้าหน้าที่ · O9 คู่มือการขอรับบริการ |
| บริการออนไลน์ | O10 ระบบบริการ e-Service |
| จัดซื้อจัดจ้าง | O11 สรุปผลการจัดซื้อจัดจ้างรายเดือน 2569 · O12 รายงานสรุปผลการจัดซื้อจัดจ้าง 2568 |

O1, O5, O8, O9, O11 และ O12 เป็นเป้าหมายลำดับแรกที่ควรยกระดับเป็น controlled source ใน `manifest/documents.yaml` เมื่อเจ้าของเอกสารยืนยันฉบับที่ใช้จริง — ปัจจุบันยังไม่ได้ลงทะเบียนเป็น controlled document

## 6. แหล่งภายใน

repository นี้เป็น **public** ดังนั้น **ห้ามคัดเนื้อหาจากระบบภายในเข้ามาใน repo** (ดู [Repository Data Boundary](repository-data-boundary.md)) สิ่งที่ลงทะเบียนได้คือ pointer เท่านั้น

| ระบบ | สถานะ | ลงทะเบียนที่ |
| --- | --- | --- |
| STeP MIS (`mis.step.cmu.ac.th`) | ต้องเข้าสู่ระบบ ยังไม่ยืนยันขอบเขตการใช้งานกับเจ้าของระบบ | `services.yaml` → `sources.step-mis`, `organization.yaml` → `internalSystems` |

ระบบภายในอื่น (อินทราเน็ต ระบบสารบรรณ ระบบการเงิน ระบบ HR ไดรฟ์ของทีม) **ยังไม่ได้ลงทะเบียน** เพราะต้องให้เจ้าของระบบระบุ URL ขอบเขตการใช้ และชั้นความลับก่อน

## 7. สถานะ URL ที่ตรวจพบ

| แหล่ง | สถานะ 2026-09-20 |
| --- | --- |
| `step-nsp-services` (`www.step.cmu.ac.th/NSP/service.php`) | **HTTP 404 — ลิงก์ตาย** ยังถูกอ้างใน `resourceResolution.discoverySources` และบริการหลายรายการ |
| `step-oit-2026` เดิม (`www1.step.cmu.ac.th`) | DNS/TLS ใช้ไม่ได้ — เปลี่ยนมาใช้ host `www` แล้ว |
| `step-service-journey`, `step-aboutus`, `step-contact`, `step-oit-2026`, `cmu-org-step`, `abplas-service`, `nstis` | เข้าถึงได้ |

ต้องขอ URL ใหม่ของหน้าบริการ NSP จากทีมสื่อสารองค์กรก่อนถอดรายการ `step-nsp-services` ออก เพราะบริการหลายรายการอ้างเป็น `sourceRefs` อยู่

## 8. วิธีใช้เอกสารนี้

1. ใช้ตอบคำถามทั่วไปเรื่องหน่วยงาน ที่อยู่ ช่องทางติดต่อ และภาพรวมบริการ
2. อ้าง `sourceRef` ทุกครั้งและระบุวันที่ตรวจแหล่ง
3. **ห้าม**ใช้แทนระเบียบ ประกาศ มติ หรืออำนาจอนุมัติ — เรื่องเหล่านี้ใช้ `manifest/documents.yaml` และ `manifest/authority.yaml`
4. ถ้าข้อมูลบนเว็บขัดกับเอกสารควบคุม ให้ยึดเอกสารควบคุมและแจ้งผู้ดูแล
5. ทบทวนทุก 90 วันตาม [Knowledge Policy](knowledge-policy.md) หรือเมื่อพบลิงก์ตาย
