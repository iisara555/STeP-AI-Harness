# STeP Agent Browser

ทดลองนำแนวคิด browser-harness มาใช้กับเบราว์เซอร์แยกภายใน STeP Desktop: Agent อ่านสถานะหน้าเว็บ เลือกเป้าหมายจากรายการที่เพิ่งอ่าน สั่งงาน แล้วอ่านผลอีกครั้ง ใช้ Electron ที่มีอยู่ ไม่ต้องติดตั้ง Python, Chrome remote debugging หรือปลั๊กอินเพิ่มสำหรับพนักงาน

## การใช้งาน

เปิดโหมดทำงานที่อนุญาตเครื่องมือ แล้วพิมพ์งานพร้อม URL เช่น “เปิดเว็บนี้ ค้นหาคำว่าอบรม และสรุปรายการที่พบ” เมื่อ Agent เรียก `browser_control` แอปจะขออนุมัติเปิดเว็บ แล้วแสดงหน้าเว็บใน**แท็บเว็บของแผงขวาในหน้าต่างหลัก** (แบบ Claude และ Codex ไม่มีหน้าต่างเด้งแยก) พนักงานตรวจหน้าเว็บก่อนอนุมัติคลิกหรือกรอกแต่ละครั้ง หากต้องลงชื่อ ให้พนักงานกรอกบัญชีและ MFA ในหน้านั้นเอง แล้วบอก Agent ให้ทำต่อ

แท็บเว็บมีแถบแท็บ (หน้าของ Agent มีไอคอนผู้ช่วย) ปุ่มย้อนกลับ ไปข้างหน้า โหลดใหม่ และปิดหน้า หน้าที่พนักงานเปิดเองส่งเข้าช่องคุยหรือส่งต่อให้ผู้ช่วยได้ หน้าเว็บวาดด้วย `WebContentsView` ทับพื้นที่ที่ UI จองไว้ (`electron/browser-dock.ts`) ถ้ามีหน้าต่างยืนยัน การแจ้งเตือน หรือเมนูทับพื้นที่นั้น แอปซ่อนหน้าเว็บชั่วคราวและแสดงภาพนิ่งแทน เพื่อไม่ให้หน้าเว็บบังกล่องยืนยัน

หน้าเว็บและผลเครื่องมือผ่าน credential guard เสมอ; การตรวจข้อมูลส่วนบุคคลและ consent เพิ่มเติมขึ้นกับ `checks.privacy` การเปิดเว็บ การคลิก การกรอก และการเลือกค่าต้องยืนยันเฉพาะครั้ง แม้ใช้ auto mode หรือเคยจำการอนุมัติเครื่องมืออื่น ไม่เก็บรหัสผ่าน ไม่แนบโปรไฟล์ Chrome/Edge ส่วนตัว และไม่จำ login ข้ามการเปิดแอป

## STeP MIS

คำขอที่ให้ทำงานใน STeP MIS เช่น "หาแบบฟอร์ม ISO ล่าสุดใน STeP MIS" จะเปิดหน้า MIS ในแท็บเว็บให้อัตโนมัติ
- **ที่อยู่ระบบ:** แอปอ่านจาก `manifest/services.yaml` (`step-mis`) แล้วสั่งให้ AI เปิดด้วย `browser_control` ก่อน
- **การลงชื่อเข้าใช้:** ผู้ดูแลรายงานเมื่อ 2 ต.ค. 2569 ว่า MIS ลงชื่อในหน้าเดิม ข้อมูลนี้ยังไม่ใช่ผลทดสอบบัญชีจริง ต้องตรวจหน้า login, MFA, session expiry และการอ่านหลัง login ตาม [acceptance checklist](desktop-release-acceptance.md)
  - เมื่อพบหน้า login, AI ไม่ได้รับข้อความหรือช่องกรอกของหน้านั้น
  - พนักงานกรอกบัญชีเองในหน้านั้นในแท็บเว็บ แล้วบอกให้ AI ทำต่อ
- **การกระทำที่มีผลจริง:** host บล็อกปุ่ม submit ของ form และเป้าหมายที่ชื่อเข้าข่ายส่ง/อนุมัติ/ลงนาม (`humanOnly`) ก่อนขออนุญาต และตรวจซ้ำหลังอนุญาต ตัวตรวจอาศัยชนิด control และชื่อ จึงไม่รับประกัน custom control ทุกแบบ พนักงานต้องตรวจเป้าหมายทุกครั้ง และดำเนินการขั้นสุดท้ายเอง
- **คำขออนุมัติ:** ตัวคัดแยกงานบล็อกคำขออนุมัติใน MIS เมื่อองค์กรเปิด `checks.authority` (ค่าเริ่มต้นปิด)
- **ถ้าผู้ดูแลปิดเครื่องมือ:** AI บอกขั้นตอนให้พนักงานเปิด MIS เอง

## ขอบเขตที่พัฒนา

- `open`: เปิด URL HTTP(S) ในแท็บเว็บ ด้วย session ชั่วคราวที่เป็นของงานนี้
- `read`: อ่านข้อความที่มีขนาดจำกัดและรายการปุ่ม/ช่องกรอก พร้อม snapshot และ reference
- `fill`, `click`: ใช้ reference ที่มีอยู่จริงจาก snapshot ล่าสุด ตรวจซ้ำหลังคนอนุมัติ และให้ Agent อ่านหน้าใหม่หลังทำงาน
- `select`: เลือกค่าจาก native single-select ด้วย `value` ที่อยู่ใน snapshot ล่าสุด; ปฏิเสธ option ที่ disabled/ไม่มีอยู่/ซ้ำกัน
- `close`: ปิดหน้าของงานนี้ การยกเลิก Agent ปิดหน้าของงานด้วย

Snapshot หมดอายุเมื่อ DOM, URL, ช่องกรอก หรือเป้าหมายเปลี่ยน การอ่านครั้งใหม่แทน snapshot เดิม การทำงานเรียงลำดับเพื่อไม่ให้คำสั่งชนกัน ผล click หมายถึงส่ง event แล้วเท่านั้น ไม่ใช่หลักฐานว่าระบบปลายทางรับรายการสำเร็จ ต้องอ่านและตรวจผล

ไม่เปิด arbitrary JavaScript/CDP ให้โมเดล ไม่รองรับ iframe, shadow DOM, custom dropdown, multi-select, upload, download, screenshot สำหรับโมเดล หรือบันทึกวิดีโอในรุ่นทดลองนี้ หน้า login ที่ตรวจพบช่อง password/OTP จะไม่คืนข้อความหรือรายการเป้าหมายให้โมเดล การนำทางข้าม origin ถูกปิด ต้องเปิดปลายทางใหม่โดยอนุมัติอีกครั้ง จึงยังไม่รับรองเว็บที่ใช้ SSO ข้ามโดเมน และเว็บที่เปลี่ยน DOM ตลอดเวลาอาจต้องอ่านซ้ำ

โหมด plan อ่านแท็บเดิมได้ แต่ไม่เปิด/คลิก/กรอก/เลือกค่า/ปิดแท็บ การปิดปุ่มใน UI ไม่ใช่กลไกบังคับสิทธิ์: host และตัวเชื่อมตรวจสิทธิ์ก่อนดำเนินการ

## สถาปัตยกรรมและต้นทาง

[Browser Harness](https://github.com/browser-use/browser-harness) เสนอการเชื่อมเบราว์เซอร์ผ่าน CDP และการสร้าง helper ระหว่างทำงาน ส่วน [MCP interface](https://github.com/browser-use/browser-harness/blob/main/docs/MCP.md) แยกคำสั่งเปิดหน้า อ่านสถานะ คลิก และกรอก STeP นำแนวคิดวงจร observe → act → verify มาใช้ แต่เขียนตัวเชื่อมแบบจำกัดคำสั่งบน Electron ที่มีอยู่ ไม่ได้ติดตั้งหรือคัดลอก upstream และไม่ให้ Agent แก้ตัวควบคุมสิทธิ์เอง

เส้นทาง: `ToolLoop → DesktopTools/ToolGate → AgentBrowser → isolated Electron world` แล้วส่งผลกลับผ่าน `DesktopTools.outgoing` หน้าเว็บถือเป็นข้อมูลที่ไม่น่าเชื่อถือ ไม่ใช่คำสั่งหรืออำนาจอนุมัติ

## การทดสอบ

`node test/browser-agent-smoke.mjs` ใช้ Electron จริงกับเว็บจำลองบน loopback ตรวจอ่าน/กรอก/คลิก/เลือกค่า/อ่านผล รวมถึงการบล็อก submit/approval ที่ตรวจพบโดยไม่เปิด approval dialog การปฏิเสธ reference เก่า เป้าหมายเปลี่ยนระหว่างอนุมัติ เจ้าของแท็บ หน้า login และ URL ที่ไม่รองรับ โดยไม่ใช้บัญชีจริงหรือโควตา AI

`test/phase2-tools.test.ts` ตรวจการส่งต่อ scope, การเรียงคำสั่ง, การอนุมัติส่งผลให้ AI, การยกเลิก และการปิดกั้นใน plan mode ข้อจำกัด: ยังไม่ได้ยืนยันกับเว็บไซต์องค์กรจริงหรือบัญชีพนักงาน และยังไม่ได้ทดสอบโมเดลจริงเลือกใช้เครื่องมือนี้
