# ผลแก้ UX audit — 1 ตุลาคม 2026

อ้างอิง [รายงานก่อนแก้](ux-audit-2026-10-01.md) คะแนนเดิม 57/100 เป็น baseline ไม่เพิ่มคะแนนอัตโนมัติจากจำนวนข้อที่แก้

| ข้อ | การแก้และหลักฐาน | สถานะ |
|---|---|---|
| F01 สถานะพร้อม | ข้าม AI แล้วแสดง “บันทึกการตั้งค่าแล้ว” ขั้น AI แสดงทำภายหลัง ปุ่มหลักกลับไปเชื่อมได้ทันที | ผ่าน UI smoke |
| F02 บัญชีที่รองรับ | หน้าหลักแสดงบัญชีที่เปิดใช้ได้จริง แยกคำแนะนำ Claude ภายนอก/Gemini ที่ยังไม่รองรับไว้ในรายละเอียด ไม่ปลดข้อจำกัดผู้ให้บริการ | UI ผ่าน; ยังไม่ปิดข้อยืนยัน OAuth บัญชีจริง |
| F03 คำขอผิดประเภท | ไม่ใช้ URL อ้างอิงเป็นข้อความจัดประเภท ให้น้ำหนักเจตนาพัฒนาตัวเชื่อม/เตรียม ISO checklist และร่างคำเชิญ พร้อม regression และ authority tests | ผ่าน 137 tests ที่เกี่ยวข้อง |
| F04 ขออนุญาตซ้ำ | เพิ่มสิทธิ์เฉพาะรอบสำหรับคำตอบและสถานะร่าง เมื่อผู้ใช้เลือกเอง ข้อมูลไฟล์/เว็บยังแยกสิทธิ์ เปลี่ยนบัญชีแล้วสิทธิ์ใช้ไม่ได้ | เส้นทางร่างจำลองลดจาก 5 เหลือ 3 ครั้ง; 19 tests สิทธิ์และเครื่องมือผ่าน |
| F05 ค่าใช้จ่าย | แสดงแพ็กเกจบัญชี, งบ API หรือเปิดแอปอื่นใกล้การเชื่อมต่อ และคงล้างคีย์เมื่อกลับโหมดง่าย | ผ่าน UI/account smoke |
| F06 ขั้นตอนก่อนเริ่ม | เส้นทางหลักเหลือ ต้อนรับ → เชื่อม AI → เสร็จสิ้น; ชื่อ/บุคลิกเลือกตั้งเพิ่มได้; OCR ติดตั้งเมื่อใช้หน้าตรวจใบเสร็จ; ปุ่มงานภาษาไทยและตัวอย่าง QS; terminal อยู่ส่วนขั้นสูง | ผ่าน UI/chat smoke |
| F07 งานบนเว็บ | ปุ่ม “ให้ผู้ช่วยทำงานบนเว็บ” เตรียมคำขอและ focus ช่องคุย แสดงข้อจำกัดและวิธีหยุด มีสถานะเว็บไซต์/ขั้นตอน | ผ่าน chat → browser → fill → click → read ยืนยันผลบนเว็บในเครื่อง; SSO/เว็บองค์กรยังไม่ยืนยัน |
| F08 หน้าต่างเล็ก | ลดตัวเลือกที่ใช้ไม่ได้ ปุ่มเชื่อมอยู่ในขอบที่เห็นและใช้ sticky; wizard เลื่อนเนื้อหาและกัก Tab ใน dialog | ผ่านตรวจตำแหน่งและ hit target ที่ 800×650 |

## ผลตรวจ

- `npm --prefix desktop run build`: ผ่าน TypeScript และ bundling; ยังมีคำเตือนขนาด bundle เดิมประมาณ 865 KB
- ชุดเฉพาะ routing/clarification/ISO/authority/governance พร้อม UX regression: 137 ผ่าน
- `phase2-tools.test.ts` และ `transmission.test.ts`: 19 ผ่าน รวมการปฏิเสธ สิทธิ์หมดอายุ เปลี่ยนผู้รับ และข้อมูลที่ต้องปิดบัง
- Electron smoke: UX audit, account connect, tool loop, browser connector, browser loop และ chat ผ่าน
- Browser loop ใช้ provider จำลองกับเว็บจริงบน localhost ไม่ใช่ AI จริง: เปิด → กรอก → อ่าน → คลิก → อ่านยืนยัน; อนุมัติการกระทำ 3 ครั้งและส่งผลเว็บให้ AI แยก 5 ครั้ง
- Python และ Node repository validators ผ่าน; `git diff --check` ผ่าน (มีคำเตือน LF/CRLF ของ lockfile เดิม)
- เคยรันชุด root ทั้งหมด: 798 ผ่าน, 26 fail, 6 skipped จาก 830 tests ในรอบนั้น; failures มาจากชุด installer เขียน config ส่วนตัวนอก sandbox ไม่ได้ และ secret-scanner test เรียก `python` ที่เครื่องนี้ไม่มี (มี `py -3`) ไม่อ้างว่าชุดทั้งหมดผ่าน ไม่ขยายสิทธิ์ไปแก้ config ส่วนตัวเพื่อทำให้ผลเขียว

## สิ่งที่ยังต้องยืนยันภายนอก

F02 ยังต้องใช้บัญชีผู้ให้บริการจริงที่ได้รับอนุญาตทดสอบ sign-in, คำตอบแรก, restart และ token expiry; F07 ยังต้องมีเว็บองค์กรและเส้นทาง SSO ที่กำหนดชัด การแก้โค้ดและผลจำลองไม่พิสูจน์สองเรื่องนี้ ยังไม่ประกาศรองรับ upload/download/iframe หรือ OAuth ส่วนตัวครบทั้งสามค่าย

ยังไม่ได้ทำ employee study 5 คนตามรายงานเดิม การเปลี่ยนแปลงอยู่ใน `main` แล้ว (commit `0d7481a`) แต่ยังไม่ deploy ให้พนักงาน และต้องปรับ selector ของ `phase4-smoke` และ `phase6-smoke` ตามป้ายภาษาไทยและสิทธิ์สถานะร่างที่เพิ่มใหม่
