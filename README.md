# STeP AI

คู่มือเริ่มต้นสำหรับพนักงาน และจุดอ้างอิงสำหรับผู้ดูแล STeP AI Harness

STeP AI เป็นชุด workspace สำหรับนำ AI มาช่วยงานของ STeP / RSP North โดยมีบริบทองค์กร วิธีทำงาน แหล่งอ้างอิง และขอบเขตอำนาจประกอบคำตอบ พนักงานเปิดโฟลเดอร์ด้วยโปรแกรม AI ที่องค์กรอนุมัติ แล้วพิมพ์งานภาษาไทยได้โดยไม่ต้องจำชื่อ Skill หรือใช้ Git/Terminal

**เริ่มใช้งาน:** [ใบเริ่มต้นสั้น](START-HERE.md) · [คู่มือพนักงานฉบับเต็ม](docs/employee-guide.md) · [ขอความช่วยเหลือ](SUPPORT.md)

| รายการใน source ปัจจุบัน | จำนวน |
| --- | --- |

| กลุ่ม routing | **5 กลุ่ม** |
| Skills | **49 Skills** |
| Playbooks | **5 Playbooks** |
| Actions | **4 Actions** |

Router มีเส้นทางเลือก Skill 47 รายการ ส่วน `step-router` ทำหน้าที่จัดเส้นทางเอง ดูรายการต้นทางได้ที่ [Skills](manifest/skills.yaml), [Router index](manifest/router-index.yaml), [Playbooks](manifest/playbooks.yaml) และ [Actions](manifest/actions.yaml)

**Release baseline ที่บันทึกไว้คือ v0.7.2** ส่วนชุดที่เตรียมสำหรับ Pilot รอบนี้และ `package.json` ระบุ **v0.7.3** ยังไม่ใช่คำยืนยันว่าเผยแพร่ GitHub Release แล้ว ตารางนี้นับจาก source ไม่ใช่รายการรับรองของ ZIP ที่พนักงานได้รับ ต้องตรวจ checksum ของชุดที่นำไปใช้ด้วย

ชุดติดตั้งที่แจกพนักงานมาจาก **release tag เท่านั้น** ไม่ใช่จาก `main` ผู้ดูแลต้องผ่าน Release Gate และแจกผ่านช่องทางที่องค์กรอนุมัติ ดูสถานะ Pilot และการดูแลแต่ละสัปดาห์ใน [Pilot Operations](docs/pilot-operations.md)

ข้อยกเว้นเฉพาะการทดสอบที่ผู้ใช้ขอครั้งนี้: Pilot ใช้ candidate v0.7.3 ที่ตรวจในเครื่องแล้วผ่านช่องทางภายใน โดย STeP AI Geek ยืนยันไฟล์และ checksum ก่อนเริ่ม ไม่ถือเป็นการเผยแพร่รุ่นทั่วไป

## เริ่มใช้งาน

### 1. รับชุดติดตั้งจากองค์กร

ดาวน์โหลด ZIP จาก **Shared Drive หรือช่องทางภายใน** ที่ทีมแจ้งว่าเป็นชุดติดตั้งที่อนุมัติแล้ว หากเข้าไม่ได้ ให้ติดต่อหัวหน้าทีมหรือผู้ประสานงานทีมตาม [STeP AI Support](SUPPORT.md)

**อย่าใช้ไฟล์จาก Public GitHub Release** แทนช่องทางภายในโดยถือว่าได้รับอนุมัติอัตโนมัติ การเปิดให้ดาวน์โหลดได้กับสิทธิ์แจกจ่ายภายในเป็นคนละเรื่อง

### 2. แตก ZIP แล้วเปิดตัวติดตั้ง

| ระบบ | ไฟล์ที่เปิด |
| --- | --- |
| Windows | `Install-STeP-AI.bat` |
| macOS | `Install-STeP-AI.command` |

บน macOS หากระบบเตือนเรื่องผู้พัฒนา ให้ตรวจที่มาของไฟล์ก่อน แล้วใช้คลิกขวา **Open** หรือ **Open Anyway** ตามขั้นตอนขององค์กร

ตัวติดตั้งเตรียม Node.js runtime เมื่อจำเป็น แสดงรายชื่อ 22 ทีม และสร้าง instruction สำหรับโปรแกรม AI ที่รองรับ คุณเลือกทีมหลักได้ทันที หรือกด `0` / Enter เพื่อข้ามแล้วเลือกภายหลัง พนักงานไม่ต้องติดตั้ง Python หรือ Git เพื่อเริ่มใช้งาน

### 3. เปิดโฟลเดอร์และลองงานแรก

เปิดโฟลเดอร์ STeP AI ด้วยโปรแกรม AI ที่องค์กรอนุมัติ แล้วพิมพ์ในแชท:

> เริ่มใช้งาน STeP AI

หรือเริ่มงานทันที:

> ช่วยตรวจเอกสารนี้ก่อนส่ง

แนบเฉพาะไฟล์หรือส่วนที่จำเป็น ถ้ายังไม่เลือกทีม ระบบยังรับคำถามได้ และจะถามข้อมูลที่มีผลต่อการทำงานเมื่อจำเป็น

เมื่อเริ่มใช้งานแล้ว คุณควร:

- รู้ว่าจะดาวน์โหลดไฟล์จากที่ไหน
- ติดตั้งได้บน Windows หรือ macOS
- เลือกทีมและเปิดโฟลเดอร์ด้วย AI ที่องค์กรอนุมัติ
- พิมพ์งานแรกเป็นภาษาไทยได้
- รู้ว่าเมื่อใดต้องหยุดให้มนุษย์ยืนยัน
- รู้ว่าจะส่งปัญหาผ่าน [STeP AI Support](SUPPORT.md) อย่างไร

## ตัวอย่างคำขอ

บอกงานและผลลัพธ์ที่ต้องการด้วยภาษาของคุณเอง ตัวอย่างเหล่านี้มี routing regression รองรับใน source ปัจจุบัน

| งาน | ตัวอย่างที่พิมพ์ได้ |
| --- | --- |
| ตรวจเอกสารก่อนส่ง | ช่วยตรวจเอกสารนี้ก่อนส่ง สรุปจุดที่ขาดและสิ่งที่ฉันต้องแก้เอง |
| สรุปประชุมและแยกสิ่งที่ต้องทำต่อ | สรุปการประชุมนี้ แยกมติ งานที่ต้องทำ ผู้รับผิดชอบ วันครบกำหนด และเรื่องที่ยังรอยืนยัน |
| ร่างหนังสือหรือข้อความสื่อสาร | ร่างหนังสือขอความอนุเคราะห์ใช้สถานที่ด้วยภาษาสุภาพ กระชับ และให้ฉันตรวจทานก่อนส่ง |
| ตรวจหรือร่าง TOR และงานจัดซื้อ | ช่วยตรวจ TOR นี้ แยกข้อเท็จจริง ความเสี่ยง และข้อมูลที่ต้องให้เจ้าของงานยืนยันก่อนส่ง AFP |
| วางแผนโครงการและทำ Timeline/Gantt | เอา TOR นี้มาแตกกิจกรรม ระยะเวลา milestone และ dependency แล้วเตรียมแผนสำหรับทำ Gantt |
| ตรวจข้อมูลส่วนบุคคลและปิดบังก่อนส่ง | ช่วยตรวจเอกสารนี้ว่ามีข้อมูลส่วนบุคคลหรือ credential ที่ไม่ควรส่งต่อหรือไม่ และเสนอจุดที่ควรปิดบัง |
| เตรียมตรวจ ISO | ช่วยเตรียมเอกสารสำหรับ audit ISO ปีนี้ |
| เตรียม prompt ภาพ | ขอ prompt ภาพโปสเตอร์งานสัมมนา |

งานหลายขั้นสามารถบอกในคำขอเดียวได้ เช่น สรุปประชุมแล้วทำแผนงานต่อ ระบบมี Playbook สำหรับ TOR → Project Plan, Meeting → Action Plan, ISO Audit Readiness และ Skill → Pilot โดยเปิดใช้ Skill ตามขั้นตอนที่เกี่ยวข้อง

การสร้าง Sheet/XLSX หรือทำงานกับบริการภายนอกขึ้นกับเครื่องมือและสิทธิ์ที่มี ระบบต้องมีหลักฐานผลลัพธ์ก่อนอ้างว่าสร้างไฟล์หรือดำเนินการสำเร็จ สำหรับ TOR จะแยกข้อเท็จจริงจากสมมติฐานและใช้หนึ่ง TOR ต่อหนึ่งงาน เว้นแต่ผู้ใช้ระบุให้รวม

## เมื่อคำขอยังไม่ชัด ระบบทำอย่างไร

source ล่าสุดปรับการถามต่อให้ทำงานดังนี้:

1. ตรวจขอบเขตอำนาจก่อนเลือกเส้นทาง รวมถึงข้อความที่ผู้ใช้ตอบเพิ่มเติม
2. ถ้ารู้ว่างานคืออะไร ให้เลือก Skill หรือ Playbook ที่ตรงงานและโหลดเฉพาะบริบทที่ต้องใช้
3. ถ้ายังไม่ชัด ให้ถามข้อมูลที่ขาดทีละข้อ เช่น เอกสารใช้ทำอะไร หรือต้องการผลลัพธ์แบบไหน โดยรวมคำตอบกับคำขอเดิม
4. หากถามแล้วยังแยกงานไม่ได้ ให้แสดงเมนูหมายเลขที่อธิบายด้วยภาษางาน แทนการวนถามคำถามเดิม ผู้ใช้เลือกหมายเลขหรือข้อความตัวเลือกได้

คำตอบอย่าง “อันไหนก็ได้” หรือหมายเลขนอกเมนูจะไม่ถูกใช้เลือกเส้นทางเอง และการเลือกเมนูไม่ข้ามข้อจำกัดเรื่องอำนาจอนุมัติ ถ้างานหลายขั้นตรงกับหลาย Playbook ระบบจะให้ระบุงานที่ต้องการก่อนเริ่ม

รายละเอียดทางเทคนิคอยู่ใน [Router specification](docs/step-router.md) และ [Context Efficiency](docs/context-efficiency.md)

## ขอบเขตการทำงานและข้อมูล

AI ช่วยสรุป ตรวจ ร่าง เปรียบเทียบ วางแผน และเตรียมหลักฐานได้ โดยแยกข้อมูลที่ยืนยันแล้ว สมมติฐาน และสิ่งที่ยังต้องถามเจ้าของงาน

| ลักษณะงาน | ขอบเขต |
| --- | --- |
| ร่างเอกสาร วิเคราะห์ หรือสร้างไฟล์งานที่ย้อนกลับได้ | ทำตามคำขอและ Action Contract ของงานนั้น |
| ส่งฟอร์ม จองทรัพยากร ส่งอีเมล หรือเผยแพร่จริง | ต้องผ่านจุดยืนยันที่เกี่ยวข้องก่อนดำเนินการ |
| อนุมัติงบ สั่งจ่าย ตัดสินผู้ชนะจัดซื้อ ลงนาม หรือรับรอง QMS | เป็นอำนาจของมนุษย์ AI ช่วยเตรียมข้อมูลประกอบได้ |

ก่อนแนบเอกสาร:

- ใช้เฉพาะโปรแกรม AI และช่องทางที่องค์กรอนุมัติ
- เปิด `Check-Privacy-STeP-AI.bat` / `Check-Privacy-STeP-AI.command` ตรวจไฟล์บนเครื่องก่อนแนบ แล้วตรวจผลและสิทธิ์ตาม [คู่มือตรวจก่อนแนบ](docs/privacy-preflight.md)
- ส่งเฉพาะข้อมูลจำเป็น ห้ามใส่รหัสผ่าน, token, cookie, MFA หรือ secret
- ถ้าระบบแจ้งข้อมูลความเสี่ยงสูง ให้หยุดและติดต่อเจ้าของข้อมูลหรือผู้รับผิดชอบงาน

การตรวจไม่พบข้อมูลอ่อนไหวไม่ได้รับรองว่าเอกสารเผยแพร่ได้ และการมี Skill ไม่ได้หมายความว่ามี SOP/ระเบียบฉบับอนุมัติครบทุกเรื่อง หากขาดแหล่งอ้างอิงต้องระบุว่ายังรอยืนยัน

ตัวตรวจอ่าน PDF text layer/DOCX ได้บนเครื่อง แต่ไม่มี OCR และไม่ดักการแนบตรงเข้า AI client ผลปิดบังข้อความไม่ใช่การปิดบัง PDF/DOCX ต้นฉบับ

อ่านเพิ่มเติม: [Privacy Gate](rules/data-classification.md) · [Browser & Credential Safety](rules/browser-credential-safety.md) · [Action Verification](docs/action-verification.md)

## ไฟล์งาน การอัปเดต และความช่วยเหลือ

จัดเก็บไฟล์ส่งมอบใต้ `output/` ตามทีม ปี เดือน และประเภทงาน โดยใช้ปี ค.ศ. และเพิ่มเลขเวอร์ชันเมื่อชื่อซ้ำ เช่น:

```text
output/CC/2026/09/presentation/20260920_CC_presentation_STeP-Booth-CMU_v01.pptx
```

เมื่อองค์กรแจ้งรุ่นใหม่ เปิด `Update-STeP-AI.bat` บน Windows หรือ `Update-STeP-AI.command` บน macOS ตัวอัปเดตสำรองรุ่นเดิมและรักษาไฟล์ส่วนตัวกับงานที่แก้ในเครื่องตามกติกาการอัปเดต

หากติดตั้งหรืออัปเดตไม่สำเร็จ ให้ถ่ายภาพหน้าจอพร้อมข้อความผิดพลาด ปิดบังข้อมูลอ่อนไหว แล้วส่งให้หัวหน้าทีมหรือผู้ประสานงานทีมผ่าน [STeP AI Support](SUPPORT.md)

หาก AI เลือกงานผิดหรือตอบไม่ถูก ใช้ `Feedback-STeP-AI.bat` / `Feedback-STeP-AI.command` เพื่อเตรียม `FEEDBACK.md` ส่วนคำขอให้ช่วยงานใหม่ใช้ `REQUEST_NEW_TASK.md` แล้วส่งผ่านช่องทางภายในของทีม

### ตรวจ source ในเครื่อง

ใช้ Node.js 20 ขึ้นไปและ Python 3.10 ขึ้นไปสำหรับการตรวจ repository:

```sh
npm run validate
npm test
```

ตัวเรียก validator ค้น `python`, `python3` หรือ `py -3` บน Windows แล้วรัน `scripts/validate_repo.py` ส่วน CI ใช้ Python ตรวจไฟล์โดยตรง ข้อกำหนด Python นี้ใช้กับผู้ดูแลที่ตรวจ source ไม่ใช่พนักงานที่เปิด workspace

คำสั่งสำหรับตรวจ routing โดยไม่ต้องติดตั้ง CLI แบบ global:

```sh
node bin/step-ai.js ask "ช่วยตรวจ TOR ฉบับนี้หน่อย" --json
node bin/step-ai.js ask "ช่วยดูเอกสารนี้หน่อย ต้องแนบอะไร" --answer "เป็นใบเสร็จค่าอาหารจัดประชุม" --json
node bin/step-ai.js doctor --employee
```

`ask` คืนเส้นทางและข้อมูลประกอบให้ AI/adapter ใช้งาน ไม่ได้ดำเนินงานภายนอกให้เสร็จด้วยตัวเอง

### Repository visibility

ตามสถานะที่บันทึกใน [Repository Visibility & Data Boundary](docs/repository-data-boundary.md) ณ วันที่ 20 กันยายน 2569 repository นี้มีสถานะ **Public** ทุกไฟล์ที่ commit จึงต้องพร้อมเปิดเผยต่อสาธารณะ เก็บ controlled SOP/WI, PII, ข้อมูลลูกค้า, credentials และข้อมูลภายในที่ยังไม่ได้อนุมัติไว้ในระบบต้นทางที่มีสิทธิ์เข้าถึง

การเปลี่ยน source, การผ่าน automated tests และการสร้าง ZIP ยังไม่เท่ากับการอนุมัติแจกจ่าย ก่อนออก release ต้องตรวจช่องทางแจกจ่าย ขอบเขตข้อมูล และ Release Gate ตามเอกสาร Pilot
