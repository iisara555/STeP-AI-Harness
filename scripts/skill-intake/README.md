# ช่องทางรับ Skill ที่พนักงานเสนอ (Apps Script)

ปุ่ม "เสนอให้องค์กรใช้" ใน STeP Desktop ส่ง Skill ที่ผ่านการตรวจอัตโนมัติมาที่ Google Sheet "Feedback & Skill Promoting"
ผ่าน Apps Script web app ใน [`Code.gs`](Code.gs) พนักงานไม่ต้องมีบัญชี GitHub

## สิ่งที่ได้รับต่อหนึ่งคำขอ

- หนึ่งแถวในแท็บ **Skill ที่เสนอ** (สคริปต์สร้างแท็บและหัวตารางให้เองเมื่อรับคำขอแรก)
- หนึ่งโฟลเดอร์ใน Google Drive ชื่อ `<เลขที่> <ชื่อ Skill>` เก็บไฟล์ข้อความของ Skill ทุกไฟล์ (ชีตเก็บแค่ลิงก์)
- ส่งไฟล์ชุดเดิม (digest เดิม) ซ้ำ จะได้เลขที่เดิมและไม่เพิ่มแถว
- รับได้สูงสุด 200 คำขอต่อวัน กันการส่งรัว ๆ

หัวตาราง:

| ส่งเมื่อ | เลขที่ | ชื่อ Skill | Skill ในชุด | เวอร์ชัน | Digest | ผู้เสนอ | ทีม | ผลตรวจอัตโนมัติ | ข้อที่พบ | ใช้แล้ว (ครั้ง) | โฟลเดอร์ไฟล์ | รุ่นแอป | สถานะ | ผู้ตรวจ | หมายเหตุผู้ตรวจ |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

ผู้ดูแลกรอกสามคอลัมน์ท้าย (สถานะ เริ่มที่ "รอตรวจ", ผู้ตรวจ, หมายเหตุ) เอง สคริปต์ไม่แก้แถวเดิม
ชื่อผู้เสนอแสดงในองค์กรได้เพราะผู้เสนอกดยืนยันก่อนส่ง (แอปบันทึก `orgConsent` ไว้ข้าง Skill)

## ตั้งค่าครั้งแรก (ผู้ดูแล)

1. เปิด Sheet "Feedback & Skill Promoting" แล้วไปที่ **ส่วนขยาย > Apps Script**
2. ลบโค้ดตัวอย่าง วางเนื้อหา `Code.gs` ทั้งไฟล์ แล้วกดบันทึก
3. (ไม่บังคับ) ถ้าต้องการให้ไฟล์ Skill ไปอยู่ในโฟลเดอร์ที่มีอยู่แล้ว: **การตั้งค่าโปรเจ็กต์ > คุณสมบัติของสคริปต์** เพิ่ม
   `SKILL_FOLDER_ID` = รหัสโฟลเดอร์ใน Drive (ส่วนท้ายของลิงก์โฟลเดอร์) ถ้าไม่ตั้ง สคริปต์สร้างโฟลเดอร์ "STeP Skill ที่เสนอ" ให้เอง
4. กด **ทำให้ใช้งานได้ > การทำให้ใช้งานได้รายการใหม่** เลือกประเภท **เว็บแอป**
   - ดำเนินการในฐานะ: **ฉัน** (เจ้าของ Sheet)
   - ผู้มีสิทธิ์เข้าถึง: **ทุกคน** (แอปส่งโดยไม่ต้องลงชื่อ Google)
5. อนุญาตสิทธิ์ที่ Google ขอ (Sheet และ Drive ของเจ้าของ) แล้วคัดลอก URL ที่ลงท้ายด้วย `/exec`
6. ใส่ URL ในไฟล์นโยบายของเครื่องพนักงาน (`%ProgramData%\STeP\desktop-policy.json` บน Windows,
   `/Library/Application Support/STeP/desktop-policy.json` บน Mac):

   ```json
   { "skillPacks": { "submitUrl": "https://script.google.com/macros/s/<รหัสการทำให้ใช้งานได้>/exec" } }
   ```

   ถ้ามี `skillPacks.approvedDigests` อยู่แล้ว ให้ใส่ `submitUrl` ไว้ในวัตถุเดียวกัน แอปรับเฉพาะ URL ของ
   `script.google.com` ที่ลงท้าย `/exec` ไม่มีค่านี้ = ไม่แสดงปุ่ม
7. เปิดแอปใหม่ ในหน้า Skill Packs ปุ่ม "เสนอให้องค์กรใช้" จะขึ้นใต้ Skill ที่ผ่านการตรวจ

แก้ `Code.gs` ภายหลัง: วางโค้ดใหม่ แล้ว **จัดการการทำให้ใช้งานได้ > แก้ไข > เวอร์ชันใหม่** เพื่อให้ URL เดิมใช้โค้ดใหม่

## แอปส่งอะไรบ้าง

แอปส่งเฉพาะ Skill แบบข้อความที่ไม่มี Hooks หรือ Agent และผลตรวจไม่ "ไม่ผ่าน" ไฟล์ทุกไฟล์ผ่านการตรวจข้อมูลส่วนบุคคล
และรหัสลับตอนนำเข้าและก่อนส่งอีกครั้ง แล้วพนักงานต้องกดยืนยันในหน้าต่างที่บอกว่าจะส่งอะไรไปที่ไหน ข้อมูลที่ส่ง:
ไฟล์ Skill, ผลตรวจ, จำนวนครั้งที่ใช้บนเครื่องนั้น, ชื่อและทีมของผู้เสนอ และรุ่นแอป

## ขั้นต่อไปหลังรับเรื่อง (ผู้ดูแล)

ผู้ดูแลพิจารณาในชีต (คอลัมน์สถานะ ผู้ตรวจ หมายเหตุ) แล้วใช้ [`admin.mjs`](admin.mjs) ในเครื่องที่ clone repository นี้ไว้
เริ่มจากเปิดลิงก์ในคอลัมน์ "โฟลเดอร์ไฟล์" กด **ดาวน์โหลด** ทั้งโฟลเดอร์ แล้วแตกไฟล์ zip

1. **ตรวจซ้ำ** ว่าไฟล์ที่ดาวน์โหลดตรงกับที่พนักงานส่ง และยังผ่านการตรวจ:

   ```sh
   node scripts/skill-intake/admin.mjs check <โฟลเดอร์ที่แตกไฟล์> --digest <ค่าในคอลัมน์ Digest>
   ```

   สคริปต์คืนชื่อไฟล์จาก Drive (`a__b.md` กลับเป็น `a/b.md`) ตรวจข้อมูลส่วนบุคคลและรหัสลับ ชนิดไฟล์ และ `pack.json`
   แบบเดียวกับตอนนำเข้าในแอป ตรวจมาตรฐาน v2 และความปลอดภัยซ้ำ แล้วเทียบ digest กับชีต digest ไม่ตรง = ไฟล์ใน Drive
   ถูกแก้หลังส่ง ห้ามใช้ชุดนั้น

2. **นำร่องกับทีม**:

   ```sh
   node scripts/skill-intake/admin.mjs pilot <โฟลเดอร์> --digest <Digest> --out <โฟลเดอร์สำหรับแจกทีม> [--policy <desktop-policy.json เดิม>]
   ```

   สคริปต์พิมพ์นโยบายที่ต้องใส่ในเครื่องของทีม (`features.skillPacks: true` และ digest ใน `skillPacks.approvedDigests`
   ถ้าให้ `--policy` จะรวมกับค่าเดิมให้) และโฟลเดอร์ที่ทุกเครื่องในทีมต้องนำเข้าในหน้า Skill Packs สคริปต์ไม่เขียนไฟล์นโยบายเอง
   เลิกนำร่องได้โดยลบ digest ออกจากนโยบาย

3. **เสนอเข้า repository เป็น Skill ขององค์กร** (บน branch ใหม่):

   ```sh
   node scripts/skill-intake/admin.mjs add <โฟลเดอร์> --digest <Digest> --owner <รหัสทีมใน manifest/teams.yaml> \
     [--contributor "<ชื่อผู้เสนอ>" --team "<ทีม>" --date YYYY-MM-DD] [--namespace common] [--dry-run]
   ```

   สคริปต์คัดลอก Skill ไปที่ `skills/<namespace>/<ชื่อ>/` และเพิ่มรายการใน `manifest/skills.yaml` ที่ stage `draft`
   พร้อม `contributors: ["ชื่อ / ทีม / วันที่"]` แล้วรัน `validate_repo.py` และบอกสิ่งที่ Skill ใหม่ทุกตัวยังต้องมีก่อนเปิด PR
   (รายการใน router-index, evals, จำนวน Skills ในเอกสาร, rebuild plugin) สคริปต์ไม่ commit หรือ push เอง

   repository นี้เป็นสาธารณะ ใส่ `--contributor` เฉพาะเมื่อผู้เสนอยินยอมให้แสดงชื่อนอกองค์กร ถ้าไม่แน่ใจให้ใส่แค่ `--team`
   หรือไม่ใส่เลย

ทดสอบแบบไม่ต่อ Google: `node --test test/skill-intake.test.js test/skill-intake-admin.test.js`
