# ช่องทางรับ Skill ที่พนักงานเสนอ (Apps Script)

ปุ่ม "เสนอให้องค์กรใช้" ใน STeP Desktop ส่ง Skill ที่ผ่านการตรวจอัตโนมัติมาที่ Google Sheet "Feedback & Skill Promoting"
ผ่าน Apps Script web app ใน [`Code.gs`](Code.gs) พนักงานไม่ต้องมีบัญชี GitHub

## สิ่งที่ได้รับต่อหนึ่งคำขอ

- หนึ่งแถวในแท็บ **Skill ที่เสนอ** (สคริปต์สร้างแท็บและหัวตารางให้เองเมื่อรับคำขอแรก)
- หนึ่งโฟลเดอร์ใน Google Drive ชื่อ `<เลขที่> <ชื่อ Skill>` เก็บไฟล์ข้อความของ Skill ทุกไฟล์ (ชีตเก็บแค่ลิงก์)
- ส่งไฟล์ชุดเดิม (digest เดิม) ซ้ำ จะได้เลขที่เดิมและไม่เพิ่มแถว
- คอลัมน์ท้าย **บัญชีที่ยืนยัน** คืออีเมลองค์กรที่ Google ยืนยันแล้ว ใช้ดูว่าใครส่งจริง (ชื่อและทีมเป็นค่าที่พนักงานพิมพ์เอง)

## ความปลอดภัยของช่องทาง (ตั้งแต่ STeP Desktop รุ่นถัดจาก 0.6.39)

web app ต้องเปิดให้ "ทุกคน" เรียกได้ เพราะแอปไม่มี session ของเบราว์เซอร์ Google และ repository นี้เป็นสาธารณะ
ใครก็รู้ URL ได้ สคริปต์จึงไม่เชื่อชื่อที่ผู้เรียกพิมพ์มา แต่ตรวจดังนี้:

- **ต้องมีบัญชี Google ขององค์กรที่ยืนยันแล้ว** ทุกคำขอต้องแนบ Google ID token (`identity`) จากการเชื่อมบัญชี Google
  ในแอป สคริปต์ตรวจลายเซ็นกับ Google (`oauth2.googleapis.com/tokeninfo`) แล้วตรวจว่าออกให้ STeP Desktop
  (`aud` = OAuth client ของแอป), อีเมลยืนยันแล้ว, โดเมน (`hd`) เป็น `step.cmu.ac.th` และยังไม่หมดอายุ (ราว 1 ชั่วโมง)
  ไม่มีรหัสลับในโค้ดหรือในแอป คำขอที่ไม่ผ่านได้ `IDENTITY` และไม่ถูกนับโควตา ไม่เขียนชีตหรือ Drive
- **ตรวจรูปแบบก่อนเรียก Google** token ที่รูปแบบหรือค่าข้างในผิด (คนละ client, คนละโดเมน, หมดอายุ) ถูกปฏิเสธโดยไม่เรียก
  Google เลย token ที่ผ่านแล้วจำไว้ใน cache จนหมดอายุ และเรียก Google ได้ไม่เกิน 2,000 ครั้งต่อวัน (`BUSY` เมื่อเกิน)
- **โควตาต่อบัญชี** เสนอ Skill ได้ 5 ชุด และแจ้งปัญหา/เสนอแนะได้ 20 เรื่อง ต่อบัญชีต่อวัน (`SENDER_LIMIT`)
  เพดานรวม 200 คำขอต่อวันยังอยู่ (`LIMIT`) ตัวนับเก็บใน Script Properties เป็น hash ของบัญชี (มี salt สุ่ม)
  ไม่เก็บอีเมล และลบตัวนับของวันก่อนให้เอง
- **ขนาดและรูปแบบ** Skill ทั้งคำขอไม่เกิน 2.5 ล้านตัวอักษร ไฟล์ละไม่เกิน 200,000 รวมไม่เกิน 2 ล้าน ไม่เกิน 120 ไฟล์
  ผลตรวจ (findings) ต้องมีรูปแบบที่แอปสร้าง แจ้งปัญหาไม่เกิน 20,000 ตัวอักษร
- **ทุกช่องเป็นข้อความ** ค่าที่ขึ้นต้นด้วย `=` `+` `-` `@` (รวมหลังช่องว่าง) ในทุกคอลัมน์จะถูกใส่ `'` นำหน้า ชีตจึงไม่รันเป็นสูตร

ใช้กับองค์กรหรือ OAuth client อื่น: ตั้ง Script Properties `ALLOWED_DOMAINS` และ/หรือ `ALLOWED_CLIENT_IDS`
(คั่นด้วยจุลภาค) แทนค่าในโค้ด

ที่ยังกันไม่ได้: คนนอกยังยิงคำขอขยะใส่ URL ได้ (Apps Script จำกัดการรันพร้อมกันเอง) แต่ไม่ได้แถว ไม่ได้ไฟล์ และไม่กินโควตา
ของพนักงาน ถ้าปลอม token ที่ค่าข้างในดูถูกต้องจนครบ 2,000 ครั้ง ช่องทางจะตอบ `BUSY` จนขึ้นวันใหม่ (ปิดได้ชั่วคราว ไม่รั่ว) พนักงานที่มีบัญชีองค์กรยังส่งเรื่องไม่เหมาะสมได้ แต่ถูกจำกัดต่อวันและผู้ดูแลเห็นบัญชีที่ส่ง

หัวตาราง:

| ส่งเมื่อ | เลขที่ | ชื่อ Skill | Skill ในชุด | เวอร์ชัน | Digest | ผู้เสนอ | ทีม | ผลตรวจอัตโนมัติ | ข้อที่พบ | ใช้แล้ว (ครั้ง) | โฟลเดอร์ไฟล์ | รุ่นแอป | สถานะ | ผู้ตรวจ | หมายเหตุผู้ตรวจ | บัญชีที่ยืนยัน |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

ผู้ดูแลกรอกคอลัมน์สถานะ (เริ่มที่ "รอตรวจ") ผู้ตรวจ และหมายเหตุเอง สคริปต์ไม่แก้แถวเดิม ชีตที่สร้างจากสคริปต์รุ่นก่อน
จะได้หัวคอลัมน์ "บัญชีที่ยืนยัน" ต่อท้ายให้เอง (ถ้าผู้ดูแลเพิ่มคอลัมน์ของตัวเองไว้หลัง "หมายเหตุผู้ตรวจ" ให้ย้ายออกก่อน)
ชื่อผู้เสนอแสดงในองค์กรได้เพราะผู้เสนอกดยืนยันก่อนส่ง (แอปบันทึก `orgConsent` ไว้ข้าง Skill)

## แจ้งปัญหา / เสนอแนะ (ตั้งแต่ STeP Desktop รุ่นถัดจาก 0.6.13)

สคริปต์เดียวกันรับเรื่องจากเมนู **ช่วยเหลือ > แจ้งปัญหา / เสนอแนะ** และจากกล่อง 👎 ใต้คำตอบ เป็นหนึ่งแถวในแท็บ
**ความเห็นจากพนักงาน** (สร้างให้เองเมื่อรับเรื่องแรก ไม่มีไฟล์ใน Drive) ใช้เพดานรวม 200 คำขอต่อวันร่วมกับการเสนอ Skill
และต้องยืนยันบัญชีองค์กรเหมือนกัน

| ส่งเมื่อ | เลขที่ | ประเภท | ข้อความ | คำตอบของ AI ที่แนบ | ผู้ส่ง | ทีม | รหัสข้อผิดพลาดล่าสุด | ระบบ | รุ่นแอป | สถานะ | ผู้ดูแล | หมายเหตุผู้ดูแล | บัญชีที่ยืนยัน |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

ประเภทเป็น ปัญหาการใช้งาน, ข้อเสนอแนะ หรือ คำตอบไม่ถูกต้อง ผู้ส่ง ทีม และบัญชีที่ยืนยันว่างเมื่อพนักงานเลือกไม่ใส่ชื่อ
(บัญชียังถูกยืนยันและนับโควตา แต่ไม่บันทึก) คำตอบของ AI
มีเฉพาะเมื่อพนักงานติ๊กแนบ ข้อความและคำตอบผ่านการตรวจข้อมูลส่วนบุคคลก่อนส่ง และพนักงานต้องกดยืนยันในหน้าต่างที่บอกว่าจะส่งอะไร
แอปไม่ส่งบทสนทนา ไฟล์ หรือร่างอื่น ผู้ดูแลกรอกสามคอลัมน์ท้ายเอง (สถานะเริ่มที่ "ใหม่")

**ต้องอัปเดต Apps Script ก่อน:** สคริปต์รุ่นเก่าจะปฏิเสธเรื่องเหล่านี้ (แอปแจ้งพนักงานว่าช่องทางยังไม่พร้อม) วาง `Code.gs`
ฉบับนี้แล้วทำตามย่อหน้า "แก้ `Code.gs` ภายหลัง" ด้านล่าง URL เดิมใช้ต่อได้ ปิดเมนูนี้ได้ด้วย `"features": { "feedback": false }`

## ตั้งค่าครั้งแรก (ผู้ดูแล)

0. (แนะนำ) ให้บัญชีที่เป็นเจ้าของ Sheet และ deploy เป็นบัญชีเฉพาะงานนี้ ที่เข้าถึงได้แค่ Sheet นี้และโฟลเดอร์ Skill ที่เสนอ
   เพราะสคริปต์รันในฐานะเจ้าของและขอสิทธิ์ Drive ทั้งบัญชี (`DriveApp` ต้องใช้) ไม่ใช่บัญชีส่วนตัวของผู้ดูแลที่เห็นไฟล์อื่นมาก
1. เปิด Sheet "Feedback & Skill Promoting" แล้วไปที่ **ส่วนขยาย > Apps Script**
2. ลบโค้ดตัวอย่าง วางเนื้อหา `Code.gs` ทั้งไฟล์ แล้วกดบันทึก จากนั้น **การตั้งค่าโปรเจ็กต์ > แสดงไฟล์ Manifest "appsscript.json"
   ในตัวแก้ไข** แล้ววาง [`appsscript.json`](appsscript.json) แทน (จำกัดสิทธิ์เหลือ Sheet นี้, Drive และการเรียก Google เพื่อตรวจ token)
3. (ไม่บังคับ) ถ้าต้องการให้ไฟล์ Skill ไปอยู่ในโฟลเดอร์ที่มีอยู่แล้ว: **การตั้งค่าโปรเจ็กต์ > คุณสมบัติของสคริปต์** เพิ่ม
   `SKILL_FOLDER_ID` = รหัสโฟลเดอร์ใน Drive (ส่วนท้ายของลิงก์โฟลเดอร์) ถ้าไม่ตั้ง สคริปต์สร้างโฟลเดอร์ "STeP Skill ที่เสนอ" ให้เอง
4. กด **ทำให้ใช้งานได้ > การทำให้ใช้งานได้รายการใหม่** เลือกประเภท **เว็บแอป**
   - ดำเนินการในฐานะ: **ฉัน** (เจ้าของ Sheet)
   - ผู้มีสิทธิ์เข้าถึง: **ทุกคน** (แอปไม่มี session เบราว์เซอร์ Google สคริปต์ตรวจบัญชีองค์กรจาก ID token ในคำขอเอง)
5. อนุญาตสิทธิ์ที่ Google ขอ (Sheet, Drive ของเจ้าของ และ "เชื่อมต่อกับบริการภายนอก" สำหรับตรวจ token) แล้วคัดลอก URL
   ที่ลงท้ายด้วย `/exec`
6. ตั้งแต่ STeP Desktop 0.6.11 URL ของ Sheet องค์กรฝังอยู่ในแอปแล้ว (`DEFAULT_SKILL_SUBMIT_URL` ใน
   `desktop/electron/policy.ts`) ทุกเครื่องเห็นปุ่มโดยไม่ต้องตั้งนโยบาย ถ้าทำการทำให้ใช้งานได้ใหม่จน URL เปลี่ยน
   ต้องแก้ค่านั้นแล้วออกรุ่นใหม่ หรือใส่ URL ใหม่ในไฟล์นโยบายของเครื่อง (`%ProgramData%\STeP\desktop-policy.json`
   บน Windows, `/Library/Application Support/STeP/desktop-policy.json` บน Mac) ซึ่งใช้แทนค่าในแอป:

   ```json
   { "skillPacks": { "submitUrl": "https://script.google.com/macros/s/<รหัสการทำให้ใช้งานได้>/exec" } }
   ```

   แอปรับเฉพาะ URL ของ `script.google.com` ที่ลงท้าย `/exec` ปิดปุ่มได้ด้วย `"features": { "staffSkills": false }`
7. ในหน้า Skill Packs ปุ่ม "เสนอให้องค์กรใช้" จะขึ้นใต้ Skill ที่ผ่านการตรวจ

แก้ `Code.gs` ภายหลัง: วางโค้ดใหม่ แล้ว **จัดการการทำให้ใช้งานได้ > แก้ไข > เวอร์ชันใหม่** เพื่อให้ URL เดิมใช้โค้ดใหม่

### อัปเดตเป็นรุ่นที่ยืนยันบัญชี (ผู้ดูแลต้องทำเองใน Apps Script)

1. รอให้ STeP Desktop รุ่นที่ส่ง `identity` ออกและพนักงานอัปเดตก่อน แอปรุ่นเก่าส่งไม่ได้หลังเปลี่ยน
   (พนักงานเห็น "ช่องทางรับ Skill ไม่รับคำขอนี้")
2. วาง `Code.gs` และ `appsscript.json` ฉบับนี้ แล้วกดบันทึก
3. กดเรียกฟังก์ชันใดก็ได้หนึ่งครั้งในตัวแก้ไข (เช่นเลือก `today` แล้วกด **เรียกใช้**) เพื่อให้ Google ถามสิทธิ์ใหม่
   "เชื่อมต่อกับบริการภายนอก" แล้วอนุญาต ถ้าไม่ทำ คำขอทุกคำขอจะล้มเหลว
4. **จัดการการทำให้ใช้งานได้ > แก้ไข > เวอร์ชันใหม่** URL เดิมใช้ต่อได้ ไม่ต้องออกแอปใหม่เพื่อเปลี่ยน URL
5. ลองส่งจากแอปรุ่นใหม่หนึ่งเรื่อง แล้วดูว่าคอลัมน์ "บัญชีที่ยืนยัน" มีอีเมลองค์กร
6. ถ้าต้องถอยกลับ: **จัดการการทำให้ใช้งานได้ > แก้ไข** เลือกเวอร์ชันก่อนหน้า

## แอปส่งอะไรบ้าง

แอปส่งเฉพาะ Skill แบบข้อความที่ไม่มี Hooks หรือ Agent และผลตรวจไม่ "ไม่ผ่าน" ไฟล์ทุกไฟล์ผ่านการตรวจข้อมูลส่วนบุคคล
และรหัสลับตอนนำเข้าและก่อนส่งอีกครั้ง แล้วพนักงานต้องกดยืนยันในหน้าต่างที่บอกว่าจะส่งอะไรไปที่ไหน ข้อมูลที่ส่ง:
ไฟล์ Skill, ผลตรวจ, จำนวนครั้งที่ใช้บนเครื่องนั้น, ชื่อและทีมของผู้เสนอ, รุ่นแอป และ Google ID token ของบัญชีองค์กร
ที่เชื่อมไว้ในแอป (ถ้ายังไม่เชื่อม แอปไม่ส่งและบอกให้เชื่อมบัญชี Google ในหน้าตั้งค่าก่อน) แอปไม่ส่ง access token
หรือ refresh token ของ Google

## ขั้นต่อไปหลังรับเรื่อง (ผู้ดูแล)

ผู้ดูแลพิจารณาในชีต (คอลัมน์สถานะ ผู้ตรวจ หมายเหตุ) แล้วใช้ [`admin.mjs`](admin.mjs) ในเครื่องที่ clone repository นี้ไว้
เริ่มจากเปิดลิงก์ในคอลัมน์ "โฟลเดอร์ไฟล์" กด **ดาวน์โหลด** ทั้งโฟลเดอร์ แล้วแตกไฟล์ zip

1. **ตรวจซ้ำ** ว่าไฟล์ที่ดาวน์โหลดตรงกับที่พนักงานส่ง และยังผ่านการตรวจ:

   ```sh
   node scripts/skill-intake/admin.mjs check <โฟลเดอร์ที่แตกไฟล์> --digest <ค่าในคอลัมน์ Digest>
   ```

   สคริปต์คืนชื่อไฟล์จาก Drive (`a__b.md` กลับเป็น `a/b.md`) ตรวจข้อมูลส่วนบุคคลและรหัสลับ ชนิดไฟล์ และ `pack.json`
   แบบเดียวกับตอนนำเข้าในแอป ตรวจมาตรฐาน v2 และความปลอดภัยซ้ำ แล้วเทียบ digest กับชีต digest ไม่ตรง = ไฟล์ใน Drive
   ถูกแก้หลังส่ง ห้ามใช้ชุดนั้น

2. **นำร่องกับทีม**:

   ```sh
   node scripts/skill-intake/admin.mjs pilot <โฟลเดอร์> --digest <Digest> --out <โฟลเดอร์สำหรับแจกทีม> [--policy <desktop-policy.json เดิม>]
   ```

   สคริปต์พิมพ์นโยบายที่ต้องใส่ในเครื่องของทีม (`features.skillPacks: true` และ digest ใน `skillPacks.approvedDigests`
   ถ้าให้ `--policy` จะรวมกับค่าเดิมให้) และโฟลเดอร์ที่ทุกเครื่องในทีมต้องนำเข้าในหน้า Skill Packs สคริปต์ไม่เขียนไฟล์นโยบายเอง
   เลิกนำร่องได้โดยลบ digest ออกจากนโยบาย

3. **เสนอเข้า repository เป็น Skill ขององค์กร** (บน branch ใหม่):

   ```sh
   node scripts/skill-intake/admin.mjs add <โฟลเดอร์> --digest <Digest> --owner <รหัสทีมใน manifest/teams.yaml> \
     [--contributor "<ชื่อผู้เสนอ>" --team "<ทีม>" --date YYYY-MM-DD] [--namespace common] [--dry-run]
   ```

   สคริปต์คัดลอก Skill ไปที่ `skills/<namespace>/<ชื่อ>/` และเพิ่มรายการใน `manifest/skills.yaml` ที่ stage `draft`
   พร้อม `contributors: ["ชื่อ / ทีม / วันที่"]` แล้วรัน `validate_repo.py` และบอกสิ่งที่ Skill ใหม่ทุกตัวยังต้องมีก่อนเปิด PR
   (รายการใน router-index, evals, จำนวน Skills ในเอกสาร, rebuild plugin) สคริปต์ไม่ commit หรือ push เอง

   repository นี้เป็นสาธารณะ ใส่ `--contributor` เฉพาะเมื่อผู้เสนอยินยอมให้แสดงชื่อนอกองค์กร ถ้าไม่แน่ใจให้ใส่แค่ `--team`
   หรือไม่ใส่เลย
